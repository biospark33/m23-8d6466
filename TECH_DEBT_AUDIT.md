### Merge strategy: merge commits, not squash (decided 2026-08-29)

**Waves 1-9 MUST be merged with a merge commit (`gh pr merge --merge`). Do not squash, do not
rebase-merge.** Wave 0 (#141) was squash-merged and that is what forced this rule.

A squash replaces a branch's commits with one new commit. In a stack where each wave is based on
the wave below it, that orphans every branch above: their copies of the squashed commits no longer
exist in the base's history, so git reads them as divergent work. #141's squash flipped #147 to
CONFLICTING, and repairing #147 (replay onto `dev`, force-push) in turn flipped #148 to CONFLICTING
with 11 conflicted files across `credentials.ts`, `status.ts` and four test suites. Attempting to
carry that repair up the stack conflicted again on wave 2's own security commit. Each squash costs
one manual conflict resolution per remaining wave, and each *rebase* repair costs another, because
rewriting a branch orphans its own children in turn.

A merge commit preserves the shared commits, so when wave N merges into `dev`, wave N+1's branch
still recognises its own history and stays mergeable. Repair-by-merge (`git merge origin/<parent>`)
is likewise preferred over repair-by-rebase for the same reason: it fixes divergence without
rewriting history the next wave depends on.

Two standing consequences while the stack is open:

- The `qds-pr-monitor` skill's Phase 4 tries `gh pr merge --squash` FIRST. That default is wrong for
  this stack — override it.
- Never force-push a wave branch that another open PR is based on. #147 was force-pushed once, out
  of necessity, after #141's squash; doing it again would break #148's in-flight conflict resolution.

Wave 0 closed F016, F087, F085 and F012 outright. F090's fix is this repo's
`sprint-status-history.md` drain — the yaml now carries current state plus its newest note only.<br />

2026-08-29, so waves 5-9 carry agent self-review rather than independent bot review. Wave 6 (#153)

## Architectural mental model

In July this repo was a verification harness pretending to be a product. Since then it built the product, and the harness became the legacy.

The new centre is the **Dark Factory v5 control plane**: `src/fleet/` admits work and mints run IDs behind a single-operator file lock (`dispatch`, `fanout` best-of-n, `rank`, `FleetLock`); `src/providers/` owns the substrate — an `exe.dev` SSH driver, per-run minted API credentials with provider-side ceilings, an append-only SQLite cost ledger, harvest, teardown and a reaper; `src/phase-engine/` runs manifest-driven phases inside the box and writes a SQLite trace; `src/pr/` + `src/reverify/` are the "lights-on head" that re-verifies a harvested tree in a worktree and opens the PR; `visualizer/` is a Vue 3 + Bun read-only UI over that trace. Around it sits the Phase-0 apparatus — `src/gate/`, `src/swarmclaw/`, `src/hindsight/`, `scripts/*-verify.ts`, `cli-anything/`, `pi-vs-claude-code-vendor/` — which is now scaffolding: the gate is still `gate-red-not-exitable` in `sprint-status.yaml:75` while 23 of 31 Dark Factory stories have shipped on top of it.

The organizing fact has changed with it. This is no longer a system that proves things about itself; it is a system that **spends real money on machines it does not own**. Its load-bearing invariants are money (ledger, per-issue caps, credential ceilings), containment (box paths, shell quoting, artifact traversal, worktree isolation) and identity (`requestId`/`runId` correlation). Per-file discipline around those is genuinely high — `fleet-lock.ts` reasons about pid recycling and zombie judgment, `cost-ledger.ts` documents why it rounds before validating, `dispatch-task.ts` does a two-stage decode-then-check on artifact paths.

The debt is therefore not inside files. It is at the **seams between them**, and it takes three shapes. First, helpers that cross a module boundary get re-typed rather than imported, and the copies diverge — the validating `usdToMicros` and the `NaN`-returning one sit two directories apart on the same money path. Second, orchestration accumulates in one function until nothing inside it can be tested in isolation. Third, and most costly: **a documented, tested, invariant-bearing path can have no caller at all**, and nothing in the build notices. `ingestCostEvent`, the `openTraceReader` half of the trace layer, the redaction map both publication CLIs default to `{}`, the P0.7 gate probe's cleanup — each is described as live in prose that no execution reaches.

This contradicts the README, which is finding F016 and the reason a new contributor's mental model would be two months and roughly 45,000 lines out of date.

- **`withTimeout` abandoning rather than cancelling the losing promise** (`timeout.ts:47`) — deliberate; the late rejection is pre-caught, and `provisionAdmittedRun` writes the port *before* expose precisely because of it (`driver.ts:701-706`).

The comment correctly identifies that a synchronous try/catch cannot catch stream EPIPE and an unhandled `error` event kills the process. Right trade, acknowledged.

- **~580 message-substring assertions across `tests/fleet/`.** Message-coupled and brittle in the abstract, but for this CLI the operator-facing message and its remediation *are* the contract (the exit table, the "tear the run down" instruction). Pinning them is correct — and it is what makes F003's extraction cheap.

- **Tests opening raw `bun:sqlite` handles to assert on rows** (16/17/10/4 across the four trace test files). Implementation-coupled by construction, but for a persistence layer the table contents are the point, and close counts exceed open counts in every file.

- **`scripts/lib/harness-notes.ts` at 43 lines with no dependencies.** Looks like a pointless module; its docblock names the exact dependency-direction problem it prevents. Correct call.

- **`tests/gitnexus/fixtures/swarmclaw.ts` still statically dead.** Same verdict as July: it exists so `gitnexus analyze` has stable symbols to index, the comment says so, and the `ponytail:` marker flags it as deliberate.
