# Edge Case Hunter — M3.1 round 1 (feature/m3-1-manager-meta-banks-l3-consolidate)

Scope: `_bmad-output/reviews/m3-1-round1/diff.patch` hunks, with landed files read to confirm each path (`src/hindsight/nightly-consolidate.ts`, `scripts/memory-nightly.ts`, `scripts/provision-hindsight-banks.ts`, `src/memgate/{gateway,forward,schemas}.ts`, `src/hindsight/{client,schemas,bank-provisioner}.ts`, `scripts/p0-9/leg-lib.ts`).

## Findings

- **Rerun lane never provisions qa/maint meta banks, then the MM leg fails against them — every provision rerun exits 1 and cannot converge** — HIGH — `scripts/p0-9/leg-lib.ts:857` + `scripts/provision-hindsight-banks.ts:466,964-990` — `rerunAwareProvision` still PUT-upserts the THREE-bank roster `[base, base-dev-meta, collective]` (untouched by this diff), and `buildProvisionEnvelope` prefers `raw.roster` over `canonicalRoster`; the rerun lane is the live-box path (base + dev-meta exist from M1.1). Unhandled state: rerun succeeds on 3 banks → `withManagerMentalModels` derives `[base-dev-meta, base-qa-meta, base-maint-meta]` from `envelope.banks[0]` → `listMentalModels(base-qa-meta)` 404s on the nonexistent bank → leg catch converts the success envelope to `{ok:false, banks:[], error:mental_model_provision_failed}` → exit 1; re-running reruns the same lane, so the run can never go green and the deployment never gains qa/maint meta banks (the nightly then fails those two banks nightly).
- **leg-lib's declared MAX_BASE_LEN mirror (52) not retuned with bank-provisioner's (50) — long-slug second run mints a junk `-2` family** — MED — `scripts/p0-9/leg-lib.ts:601-612,630-643` vs `src/hindsight/bank-provisioner.ts:170` — `safeRepoBase` truncates to 52 while the fresh lane's `truncateForSuffix` now truncates to 50; for any slug whose resolved id exceeds 50 chars, `isRerunTarget` (`existingBankIds.includes(safeRepoBase(repoSlug))`, provision script :378) checks for the 52-char id, never the provisioned 50-char one. Unhandled input: second provision of a >50-char-slug repo → rerun lane not selected → fresh lane sees the 50-char base as a collision → mints `<50char>-2` junk family; `rosterPatternClaim` (52-based shapes) also fails to claim the 50-char creations for compensation.
- **Nightly counts a non-terminal or cancelled refresh operation as success evidence (only `failed` is rejected)** — MED — `src/hindsight/nightly-consolidate.ts:307-317,363-371` — `observeRefresh` returns the first row matching model-id + created-at with no status gate, and `consolidateOneBank` checks only `op.row.status === "failed"`. Unhandled input: refresh op observed in `pending`/`processing` (later fails) or terminal `cancelled` → success receipt recording `status:"cancelled"` and exit 0, violating the AC2 fail-loud proof standard (the provisioner's own poll treats `cancelled` as failure; the nightly does not).
- **Duplicate bank ids in `deps.banks` produce a guaranteed false failure** — MED — `src/hindsight/nightly-consolidate.ts:170-197` — the array is iterated unvalidated (only emptiness is checked); a repeated bank coalesces on its second consolidate (`deduplicated:true`), and the duplicate's evidence window requires a refresh created after the SECOND consolidate completed — the only refresh (fired by the first pass) predates it, so the poll burns the remaining shared budget and returns `REFRESH_EVIDENCE_MISSING`, marking the whole run failed.
- **Unparseable `created_at` (Date.parse → NaN) silently masks existing refresh evidence** — MED — `src/hindsight/nightly-consolidate.ts:366` — `NaN > consolidateCompletedAtMs - skew` is false, so the op is filtered out; unhandled input: a drifted/locale-formatted `created_at` string on an otherwise valid refresh row → the real evidence is invisible → poll to the full 300s budget → false `REFRESH_EVIDENCE_MISSING` (fail-loud, but misattributed to the instance not firing).
- **Operations/mental-model listing cannot paginate (no offset in the client; both pollers pass limit 50 / rely on the first page)** — MED — `src/hindsight/client.ts:559-584` + `src/hindsight/nightly-consolidate.ts:362` + `scripts/provision-hindsight-banks.ts:825,885` — `listOperations`/`listMentalModels` expose only type/status/limit; unhandled state: >50 refresh ops on a bank, a create op older than page 1 (non-newest-first ordering), or >1 page of mental models → the target row/model is never seen → false `mental_model_create_timeout` (120s), false `REFRESH_EVIDENCE_MISSING`, or a duplicate create that 0.10.0 rejects (existing custom id) → leg failure. The newest-first assumption is nowhere pinned.
- **`waitForCreateOperation` has no retry around `listOperations` — one transient HTTP blip aborts the whole leg** — LOW — `scripts/provision-hindsight-banks.ts:825-843` — unlike the nightly's evidence poll (which catches and retries to the budget), a single 5xx/timeout during the create-op poll propagates as a raw `HindsightHttpError` into `withManagerMentalModels`'s generic `mental_model_provision_failed` catch — no loop-safety hazard (the throw exits), but a transient fault is converted into a provisioning failure with no create-specific code or remediation.
- **`pollIntervalMs ≤ 0` / NaN is unvalidated — hot poll loop for the full evidence budget** — LOW — `src/hindsight/nightly-consolidate.ts:358,372-374` — `sleep(0)` resolves immediately (and `setTimeout(NaN)` fires immediately), so a 0/negative/NaN interval turns the 300s default budget into a continuous hammering of `listOperations`; only the deadline bounds it.
- **No finite-clock guard in the nightly job (unlike the gateway's F-018 mirrors) — a NaN injected clock loops `observeRefresh` forever** — LOW — `src/hindsight/nightly-consolidate.ts:209,372` — `NaN + pollIntervalMs >= deadlineMs` is false, so a caller-supplied `now` returning NaN never reaches the missing-return; also `totalMs` becomes NaN → `JSON.stringify` emits `null` in the CLI envelope. `memgateDeps`/`mintRunMemoryKey` guard non-finite clocks; this module does not.
- **The shared-fresh lane now holds the provision window lock through the MM leg** — LOW — `scripts/provision-hindsight-banks.ts:1082-1090` — `opened.release()` moved after `withManagerMentalModels`, whose serial creates can poll up to 120s per bank (3× worst case ≈ 6 min) while the family lock/heartbeat window is held; a lock steal mid-MM-leg was previously impossible at this point in the flow and is now reachable (tolerated as a log line upstream, but the window is materially longer).
- **Multiple triggered mental models on one bank: preflight picks the first, evidence matches only its id** — LOW — `src/hindsight/nightly-consolidate.ts:242,365` — `find()` takes the first model with `refresh_after_consolidation === true`; an operator/foreign-tool-added second triggered model (or a server that refreshed a different one) yields refresh rows whose `mental_model_id` doesn't match → false `REFRESH_EVIDENCE_MISSING` although a refresh demonstrably fired for the bank.
- **The nightly CLI never applies the INV-MEM-1 prefix / collective-id slug gate that the provision script enforces** — LOW — `scripts/memory-nightly.ts:204-228` — `QDS_MEMORY_REPO_SLUG=qds-collective` resolves to the always-present collective, fails the meta-sibling signature, and exits 2 with remediation "run scripts/provision-hindsight-banks.ts" — which refuses the same slug for a different reason (`collective_id_slug`), sending the operator in a circle; a non-`qds-` slug with a provisioned family runs the nightly against non-qds banks with no gate at all.
- **A 2xx consolidate body of `{}` (or any key-less object) parses via the widening defaults and is only caught downstream** — LOW — `src/hindsight/schemas.ts:238-246` + `src/hindsight/nightly-consolidate.ts:281-289` — with `consolidatedCount/preservedCount/durationMs` all `.default(0)` and both wire fields optional, an empty/garbage 2xx body parses as success-shaped (`deduplicated` absent → treated as a real consolidate); the drift then surfaces as `REFRESH_EVIDENCE_MISSING` (wrong code/remediation) instead of `CONSOLIDATE_UNPARSEABLE`, misdirecting diagnosis away from the response shape.
- **`patchMentalModel` interpolates `mentalModelId` into the path with no boundary validation** — LOW — `src/hindsight/client.ts:503-523` — `bankId` is asserted via `assertBankId`, but the model id is not: an id containing `/`, `?`, or `#` rewrites the URL (all in-repo callers derive ids from `splitManagerMetaBank`, so the charset is safe today; the public method is the unguarded seam).
- **`ensureManagerMentalModels`'s emit is unguarded — a throwing caller log sink becomes a leg failure** — LOW — `scripts/provision-hindsight-banks.ts:878-901` — `opts.log` is invoked bare (the nightly's `emit` wraps its sink in try/catch); a throwing sink propagates into the generic `mental_model_provision_failed` envelope, masking the real provisioning state.
- **Test tautology: the "two polls minimum" invariant is asserted with an always-true check** — LOW — `tests/hindsight/meta-bank-provisioning.test.ts:277-281` — `expect(opIds).toBeDefined()` cannot fail (`opIds` is an array literal); the test's stated purpose ("not a single-shot read") is never actually asserted, so a regression to a single poll would stay green.
- **Malformed (non-`mgat.`) token material: wrong remediation and a blurred exit-code boundary** — LOW — `scripts/memory-nightly.ts:203-252` + `src/hindsight/nightly-consolidate.ts:264-268` — a present-but-garbage token passes the config gate, then fails per-bank as `GATEWAY_NO_AUTH` with remediation "check agent token scope (bank/verb)" (wrong advice — the token never parsed) and exits 1, while a *missing* token exits 2 as config; no pre-flight `mgat.`-shape check distinguishes the two operator errors.

## Confirmed handled

- `REFUSAL_CODE` covers all 8 `MEMGATE_REFUSAL_REASONS` members; `Record<MemgateRefusalReason, string>` makes set drift a compile error, not a runtime `undefined` code.
- `resolveBankId` sanitizes the slug (lowercase, non-alnum→`-`, dash-trimmed); empty/whitespace `QDS_MEMORY_REPO_SLUG` falls to the `qds-factory` default (`isNonEmpty`).
- Leading/trailing whitespace in the env token is trimmed by `verifyRequest`'s `Bearer ` slice + `.trim()` before credential resolution.
- Empty banks array throws `nightly-banks-empty`; missing token throws `nightly-token-missing`; `gateway.client === undefined` throws `client-missing` — all typed MemgateErrors before any work.
- Trigger `null` vs `{}` vs `{refresh_after_consolidation:false}` all route to the PATCH path (`?.` + `!== true`); `MentalModelSchema` nullish trigger + passthrough parses metadata-detail rows.
- `ConsolidateResponseSchema` accepts both the legacy counts body and the real `{operation_id, deduplicated}` wire body; `consolidatedCount:null` still fails loud (`default` folds only `undefined`).
- Every new client method interpolates only `assertBankId`-validated bank ids into paths (`[a-z0-9-]` — no encoding hazard); a bank containing `/` is refused at `bankOfPath`/`matchRoute` (scope-bank/scope-verb), never forwarded.
- `forwardScoped` with an `undefined` body degrades to the argument-less consolidate via `parseForwardBody`'s null/undefined arm (`{}` on the wire) — confirmed against `src/memgate/forward.ts`.
- Create response `mental_model_id` null forever is harmless: the value is unused (custom id is deterministic) and the post-pass drift check fails loud if the model never lands.
- PATCH 404 (model deleted mid-leg), create op `cancelled`, and poll timeout all fail the leg loud into the failure envelope; a throwing `listOperations` cannot loop `waitForCreateOperation` forever (the exception exits the loop).
- The provisioning poll budget is per-create (fresh `now() + pollTimeoutMs` per bank), not shared across the three banks.
- Evidence-deadline starvation between banks (bank 3 gets the residue of the shared budget) is documented deliberate in `NightlyDeps` and the run comment.
- ConsolidateResponseSchema widening + `Round-trip-verifier` compatibility is handled via `.default(0)` (additive; `z.infer` stays `number`).
- 50-char base → mm id 59 chars; collision `-11` base (53) → 62 chars — both ≤ 64 and regex-safe; `splitManagerMetaBank`'s leftmost `$`-anchored split returns the correct repoBankId even for lane-word-embedded bases like `qds-dev-dev-meta`.
- `QDS_MEMORY_AGENT_TOKEN` present with valid material but foreign/wrong-class scope → typed `GATEWAY_SCOPE_BANK`/`GATEWAY_SCOPE_VERB` failures with no consolidate fetch (tests 5-6).
- CLI bank-resolution failure happens before gateway construction → the pinned ledger path is never opened (test 18 pins it); a transient `listBanks` fault at start propagates to the top-level catch → exit 1 stderr fault line (contract-consistent).
- `extractExistingBankIds` narrows defensively (string / `bank_id` / `bankId` / `id` forms; `name` only when BankIdSchema-valid).
- Nightly tests cannot flake on timers: budgets are measured in injected tick-clock reads (1ms/read), not wall time, so real 1ms sleeps cannot exhaust the 40-tick evidence budget; provisioning timeout tests use wall-clock deadlines with proportional budgets.
- `listOperations` type/status free strings ride `URLSearchParams` (encoded); `?detail=` on `listMentalModels` is a closed TS union.
- Empty PATCH body `{}` is legal per `UpdateMentalModelRequest` (all-optional, openapi :19212) — and the leg never sends one.
- `createMentalModel` with an invalid bankId refuses 422 pre-fetch via `assertBankId` with no fetch issued.
- Settled-path exit code collapse (`envelope.ok ? 0 : 1` replacing `opened.code`) is behavior-neutral: `refuse()` and the rerun settle already encode exactly that.
- SIGINT/SIGTERM during poll loops: no handlers, but the design's server-side consolidate dedup makes a killed run's cron re-fire a coalesced success; no orphaned local state exists (no lock held by the nightly leg).
