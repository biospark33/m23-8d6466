# Blind Hunter — M1.3 round 2

Scope: the three diff chunks only (impl / tests / data-docs). Fresh standalone review; no repo access. Internal consistency of the diff's own artifacts was checked by hand (hit-rate math 13/23=0.5652 and median 106 both recompute correctly; 64 mintFailures = 64 redactions; probe-set ids all present in the committed mint record — those check out). Findings below are what does not.

---

## Findings

**1. Driver e2e verifier's hitRateAt5 assertion is both unsatisfiable and unfalsifiable — HIGH**
`scripts/dev/verify-m13-e2e.ts` seeds a 3-probe set and asserts `Math.abs(hitRate.aggregate.hitRateAt5 - 2 / 3) > 1e-9` → fail. But `scripts/memory/probe-recall.ts` only emits `hitRateAt5` when `perProbe.length >= MIN_PROBE_SET_SIZE` (20, per `probe-schema.ts`); at 3 probes it sets `aggregate.belowFloor = true` and withholds the rate. So the value is always `undefined`, and `Math.abs(undefined - 2/3)` is `NaN`, and `NaN > 1e-9` is always false — the check can never fail *and* can never pass meaningfully. The driver-owned branch gate green-lights regardless of what the rate would be, and the story's "driver e2e verifier … integrity pass" verification claim inherits the hole. Fix either the fixture (≥20 probes) or the assertion (expect `belowFloor`).

**2. The F-009 "no events → omit costTable" guard contradicts its own comment in the common case — MEDIUM**
`priming-report.ts` omits costTable only when `primed.runs === 0 && unprimed.runs === 0 && both totals === 0` — i.e., only at zero observed cycles. With cycles > 0 and a ledger holding no events for any of them, `costGroup` yields `{runs: 1+, totalMicroUsd: 0, meanMicroUsd: 0}` per group, the guard is false, and the report prints zeros — exactly the "all-zeros print" the adjacent comment says this guard prevents. The same file's per-run rule ("a run absent from the ledger reads 0") also zero-fills absent runs inside the groups, quietly skewing the primed-vs-unprimed mean toward whichever group is better priced. For the one report whose entire framing is "absent, not 0," the cost join is where the doctrine leaks.

**3. The committed hit-rate artifact cannot have been produced by the committed runner — MEDIUM**
`_bmad-output/evidence/memory/2026-10-07T15-52-32-492Z-hit-rate.json` perProbe rows are `{probeId, hit, rank, bank, recallMs}` — no `origin`, though the code pushes `origin` unconditionally; the aggregate has no `byOrigin`, though the code always emits it ("F-012: origin split always present"); and the artifact has no `dd22WorkingBar`/`dd22Note`, though the code writes both into every artifact. Three unconditional output fields missing means this evidence was generated by pre-round-1-patch code and never regenerated. On a branch whose credibility rests on honest evidence, shipping an artifact the shipping code cannot reproduce is a provenance gap — regenerate or label it stale.

**4. Cycle-grown probes are near-tautological instruments that can inflate the DD-22 decision input — MEDIUM**
`growProbeSet` appends probes with the fixed query `recall probe for document ${docId}` — the query literally embeds the expected document's identifier. Retrieval stacks that index document ids/metadata will self-hit on the id string, so the harness would measure id-lookup, not the semantic recall the probe set's hand-written queries measure. These auto-grown probes feed `hitRateAt5` and the `byOrigin` cycle split — both decision inputs for DD-22. Nothing in the diff flags or discounts this query class; the operator sees one blended rate.

**5. `loadP09MintRecords` tie-break claims "later write wins" but the tiebreaker is a random token — LOW**
Comment: ties fall back to filename order "with the lexicographically-LATER filename winning (later write wins)." The variable filename component is a random suffix (`-vrf9ks`, `-kvdvho`), not monotonic with write time. Two records sharing a `writtenAt` resolve to whichever random string sorts larger — arbitrary, not "later write." The comment asserts an ordering guarantee the code does not provide.

**6. `mergeMint` is copy-pasted into two modules — LOW**
Identical function bodies in `probe-recall.ts` and `priming-report.ts` (one typed `MintRecords`, the other `Map<string, Set<string>>`). Round 1's F-021 patch extracted the shared *membership* core into `mintMembershipViolations`; the merge helper feeding it was left duplicated. The next change to mint semantics (e.g., per-bank precedence rules) lands in one copy and not the other.

**7. `verify-test-slice.mjs` silently weakens its own vacuous-pass guard when `--min-pass` is omitted — LOW**
The usage line presents `--min-pass <n>` as part of the required invocation, but `Number(minPassRaw ?? "1")` defaults it to 1 — so a caller who forgets the flag gets a gate that passes with a single matching test, the near-vacuous outcome this file exists to prevent. Separately, the tally regex `^\s*(\d+)\s+pass\b` over combined stdout+stderr can be inflated by any test/fixture output that starts a line with digits followed by "pass".

**8. SideRow docstring overstates validation; growth mislabels the sourcing bank — LOW**
The interface comment claims "the 7 RecallRow keys, read defensively"; the validator checks 3 fields (runId, primed, latencyMs) and ignores `directive`, `banks`, and `chars` entirely. Downstream, `growProbeSet` credits every `recalledDocumentIds` entry to `SEED_PROBE_BANK` regardless of the row's own `banks` field, while its docstring says each candidate is labeled "with the bank that actually minted it." The mint gate limits the damage, but the provenance label on grown probes is asserted, not derived.

**9. Same lock, two contradictory contention policies — LOW**
`probe-recall.ts` retries only `RunLockedError` (a `RunLockReentrantError` is fatal); `priming-report.ts`'s growth retries both `RunLockedError` and `RunLockReentrantError` for the *same* `PROBE_WRITER_LOCK_ID` on the *same* directory. Any future caller that legitimately nests or interleaves the two paths gets fatal-vs-spin behavior depending on which file it entered through.

**10. probe-recall lock failure produces a stack trace, not the documented refusal — LOW**
The header contract says "exit 1 scoring refusal / lock failure (no artifact …)", but the lock-acquisition loop `throw`s out of `runProbeRecall`; in the CLI path (`import.meta.main`) that is an unhandled top-level rejection — bun prints a stack, exit code 1 only incidentally, and none of the documented stderr refusal shape appears. Consumers parsing refusals per the header get an unstructured crash.

**11. Failed-leg evidence contradicts itself on residue vs deletion — LOW**
`2026-10-07T11-49-36-792Z-…-vrf9ks.json`: `deleteOutcomes` says all three banks `deleted`/`already-gone`, `residue: []` is empty, yet `memoryResidue` lists 5 surviving `qds-factory` documentIds — byte-identical to `mintRecord`, i.e., a copy of the mint list, not a post-compensation listing. The story defers the *deleteOutcomes classification* as pre-existing leg-driver semantics, but this artifact ships in the diff as "honest history" and its residue fields disagree with its own compensation record.

**12. Verifier's CostLedger wiring is dead — suggests run-record integration is exercised when it is stubbed — LOW**
`verify-m13-e2e.ts` creates a `runs/` dir and passes `runsDir` to `CostLedger`, then supplies a `readRunRecord` stub that mints a synthetic keyHash for any runId — so the runs directory is never read and the run-record path is never exercised. The comment admits it ("a stub record supplies the fixture credential"), but the unused wiring makes the fixture look more end-to-end than it is.

**13. All CLI defaults are CWD-relative; running from anywhere but repo root silently degrades — LOW**
`DEFAULT_AUDIT_DB_FILE = ".sandbox/audit.db"`, `DEFAULT_PROBE_SET_FILE`, `DEFAULT_EVIDENCE_DIR`, `DEFAULT_REPORTS_DIR`, `DEFAULT_P09_EVIDENCE_DIR` are all relative. Invoked from any other directory, the CLI finds no audit db / probe set / mint dir and produces a plausible-looking zero-cycle report or a blanket label-integrity refusal ("no mint record for bank") with no hint that the working directory is the cause. Given how much of this diff is about refusing-with-reasons, the most common misfire cause is undiagnosable.

**14. `writeP09` parameter `at` shadows the module-level `at()` helper in the test file — LOW**
`tests/memory/probe-harness.test.ts` defines `function at<T>(arr, i)` used pervasively for fixture indexing, and `writeP09(target, banks, at: string, ok)` reuses the name as its timestamp parameter. Harmless today (the shadowing scope never calls the helper), but it is an accident waiting in the most fixture-dense file in the diff.
