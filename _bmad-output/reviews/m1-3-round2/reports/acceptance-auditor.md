## Findings

### 1. The branch-gate e2e verifier's hit-rate assertion is vacuous (NaN comparison can never fail)

- **AC/constraint:** DoD "Integration" evidence / round-1 finding class F-024 (vacuous verifier checks).
- **Severity:** MEDIUM
- **Evidence:** `scripts/dev/verify-m13-e2e.ts` seeds a **3-probe** fixture, below `MIN_PROBE_SET_SIZE = 20`, so `runProbeRecall` withholds the rate (`aggregate.hitRateAt5` is `undefined`, `belowFloor: true` — the F-003 behavior the story sanctions). The assertion `if (Math.abs(hitRate.aggregate.hitRateAt5 - 2 / 3) > 1e-9) fail("hitRateAt5 wrong")` therefore evaluates `Math.abs(undefined - 0.667) = NaN`, and `NaN > 1e-9` is `false` — the check passes unconditionally, today and under any regression. It asserts a guarantee it cannot exercise (the fixture can never produce a `hitRateAt5`), and it does not assert `belowFloor` either, so it would also stay silent if the floor withholding ever broke. This is the same vacuous-check class round 1 patched in `verify-test-slice.mjs`; the sibling verifier kept one. The unit suite (`"hitRateAt5" in metrics.aggregate` false below floor; 16/21 rate at 21 probes) does pin the real behavior, which is why this is not HIGH. Fix: grow the fixture to ≥ 20 probes (or assert `hitRateAt5 === undefined && belowFloor === true`) so the line is live.

### 2. The committed hit-rate evidence artifact predates the shipped code — the DoD demo evidence does not demonstrate the current implementation

- **AC/constraint:** DoD "Test (e2e demo — MANDATORY)" / Observability Contract artifact fidelity.
- **Severity:** LOW
- **Evidence:** `_bmad-output/evidence/memory/2026-10-07T15-52-32-492Z-hit-rate.json` was produced by a pre-round-1 build: its `perProbe` rows lack `origin`, its aggregate lacks `byOrigin`, and it has no `dd22WorkingBar`/`dd22Note` — all of which the current `scripts/memory/probe-recall.ts` emits unconditionally on every scored run — and its filename lacks the `-<rand6>` suffix the current code always appends. The committed interim report (`2026-10-07-interim.{json,md}`) *is* current-code-shaped (appendedProbes, dispatchFailures, F-009 notes), so only the hit-rate artifact is stale. Consequence: the committed demo artifact cannot be reproduced by the code on the branch, and the round-1 disposition "record DD-22 working bar as decision-input context in evidence+md" is only visible in code, not in any committed artifact. Cheap fix: regenerate both artifacts via the injected-fake path (no spend, per the story's mock-tier DoD).

### 3. Probe-growth candidate semantics deviate from the spec letter, without a recorded deviation

- **AC/constraint:** AC1/Technical Notes "Probe-set growth mechanism" — "appends candidate probes — recent cycle **outcome-document ids** plus new P0.9 import ids"; round-1 disposition F-012 "per-source-bank candidates".
- **Severity:** LOW
- **Evidence:** `growProbeSet` in `scripts/memory/priming-report.ts` sources side-channel candidates from `row.recalledDocumentIds` (the documents priming *recalled*), not the run outcome documents the spec names (the runId-keyed retain docs minted via receipts), and banks every side-channel candidate as `SEED_PROBE_BANK` unconditionally — the row's own `banks` field is ignored (the P0.9 leg *is* per-source-bank). The outcome is conservative, not wrong: `mintMembershipViolations` drops any candidate not minted into `qds-factory-dev-meta` (and the seed corpus is minted into all three banks with identical ids, so dev-meta probes stay truthful). But it is lossy for any other bank, it is not the candidate class the spec letter names, and neither the Dev Agent Record nor the round-1 disposition records the substitution — the recorded F-012 disposition says "per-source-bank candidates", which is only half-landed. Record the deviation (or read `row.banks`) and the finding closes.
