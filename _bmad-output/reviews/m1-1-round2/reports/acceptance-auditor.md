## Findings

- **[MED] F-005 half-fixed: the leg's 900s stale budget and the provisioner's 300s steal threshold live on the same lock file — a concurrent CLI arriving >300s into a long mint steals the leg's `provision.lock` and re-opens the exact misattribution window the fix was filed to close.** Violates AC3 ("the whole diff window is serialized … because a concurrent driver's creates landing inside this attempt's diff window would be misattributed to THIS attempt and deleted as its residue") and fix-drivers' own F-005 claim ("a concurrent CLI/other-caller run fails its own lock (`provision_in_progress`) instead of interleaving creates into the leg's diff window"). Evidence: the leg acquires the provisioner's path with its own budget — `scripts/p0-9/provision-and-import.ts:569-576` `const lockPath = deps.lockPath ?? join(homedir(), ".hindsight", "provision.lock"); const staleMs = deps.lockStaleMs ?? LEG_LOCK_STALE_MS; … isStale: ({ ageMs, pid }) => ageMs >= staleMs …` with `LEG_LOCK_STALE_MS = 900_000` (`scripts/p0-9/leg-lib.ts:176`, raised "deliberately NOT the provisioner's LOCK_STALE_MS 300s" to cover the full corpus mint) — while the provisioner/CLI steals on age alone at 300s: `src/hindsight/bank-provisioner.ts:123` `export const LOCK_STALE_MS = 300_000;` and `:147-149` `isStale: ({ ageMs, pid }) => ageMs >= LOCK_STALE_MS || …`. So the fix's protection lasts only the first 300 seconds of a window the same fix says can legitimately run 900: at t=301s a bare `bun scripts/provision-hindsight-banks.ts` deems the leg's live lock stale, steals it (atomic rename-to-claim, `src/lib/file-lock.ts` trySteal), provisions — its creates land inside the leg's post∖pre diff and are deleted as this attempt's residue — and the leg's own `release()` then only records a `warn-taken-over` diagnostic (`provision-and-import.ts:600-605`). Raising LEG_LOCK_STALE_MS made a second LEG well-behaved but changed nothing about the CLI/provisioner side of the same file. (VPS-day operator discipline makes this unlikely in practice; the AC's serialization clause and the fix's own claim are still not met.)

- **[MED] F-007's probe-create remedy is dead code on the live path — every real VPS-day run records `skipped-no-client` and probes a bank that was never created, resting the AC4 retirement proof entirely on an unverified 0.10.0 lazy-create assumption (the same class F-027 was DEFERRED for).** Violates the F-007 disposition ("Create probe bank first + classify refusal by status class" — only the second half executes live) and strains AC4's letter ("an unauthenticated retain/recall — written to a disposable probe bank `qds-probe-<timestamp>`" — a bank that is never created is not written-to unless retain lazy-creates). Evidence: the create only fires when a client is injected — `scripts/p0-9/auth-retired-check.ts:317-332` (`if (typeof probeClient?.createBank === "function") { … } else { steps.push({ step: "probe-create", outcome: "skipped-no-client (0.10.0 retain lazy-creates; refusal classes below distinguish auth from existence)" }) }`) — but `main()` passes mode only, never a client: `scripts/p0-9/auth-retired-check.ts:584` `const ev = await runLeg({ mode });`. `deps.client` exists solely in tests, so the shipped live leg NEVER takes the create path. The status-class split is the real guard, and it is good — but if 0.10.0 checks bank existence before/independently of auth on retain, the unauth probe 404s on every live run → `refused-non-auth` → `dangerRetired:false` with "neither confirmed retired nor demonstrably live" — i.e. AC4's retirement evidence is structurally unreachable as shipped, discovered only inside the GO window. The fix report states "0.10.0's retain path lazy-creates" as fact; F-027 (document_id upsert semantics) was deferred precisely because such 0.10.0 behavioral claims were judged unverified — this one should carry the same standing (a one-line `new HindsightClient({baseUrl, mode})` in main(), or a VPS-day checklist row).

- **[LOW] The CLI's rerun lane prints a different success envelope than the file's own committed stdout contract — `{ok,mode,createdInAttempt,raw}` with no `banks` and no `requestId`.** Violates the CLI's documented output contract at `scripts/provision-hindsight-banks.ts:36` ("On {ok:true} → prints {ok,banks,requestId} JSON + exit(0)") — a pre-existing line the adds-only fix worked around rather than amended. - **[LOW — flagged decision, flagged not accepted] The CLI's pre-provision snapshot fails open to the fresh lane, and under recovery-between-calls that mints exactly the `-2` junk F-025 exists to prevent, silently.** Fix-claim tension (fix-cli-client.md F-025-CLI: "listBanks transport failure yields an empty snapshot → fresh path → `provisionBanks` owns the failure envelope (-32002)").
