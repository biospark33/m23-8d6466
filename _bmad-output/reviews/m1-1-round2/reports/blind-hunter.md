- **F-022 ordering gate is satisfied by a FAILED hindsight-live run — it checks `mode`, never `ok`** — HIGH — `scripts/p0-9/leg-lib.ts:~613`
  Evidence: `if (parsed.mode === "live") return { ok: true, file: name };` — the only acceptance test is the mode stamp. `hindsight-live.ts` main() writes its evidence via `writeEvidenceOrStderr(LEG, evidence)` even on fatal refusals and leg failures, and a live-mode run stamps `mode: "live"` unconditionally (`finalize(...)`/`runLeg` never downgrade mode on failure) into `LIVE_EVIDENCE_DIR`. So the first live run fataling on env (or failing health/digest) produces a `…-p0-9-hindsight-live-*.json` with `mode:"live"`, and every downstream live leg's `scanLiveShapePrereq` passes on it. The gate proves the shape check *ran*, not that it *passed* — the AC1 ordering control is one failed first run away from being vacuous. Tests only pin the no-file and mock-stamped cases.

- **One lock path, two staleness budgets: legs hold `provision.lock` for 900 s, but the CLI's `provisionBanks` steals it at 300 s** — HIGH — `scripts/p0-9/leg-lib.ts:~176` + `scripts/p0-9/provision-and-import.ts:~576` vs `scripts/provision-hindsight-banks.ts:~445`
  Evidence: leg-lib: `export const LEG_LOCK_STALE_MS = 900_000;` … "deliberately NOT the provisioner's LOCK_STALE_MS 300s"; drivers acquire "the PROVISIONER'S OWN lock path (default ~/.hindsight/provision.lock)" with `isStale: ({ ageMs, pid }) => ageMs >= staleMs || …`. The CLI's fresh lanes call `provisionBanks({ client, repoSlug, bridgeProbe })` with no `noLock`, so the untouched provisioner internally evaluates the same lock with its own 300 s budget. A healthy-but-slow leg window (>300 s — the exact case the 900 s constant was chosen for, "a healthy-but-slow mint overrun") is therefore *stale* to a concurrent CLI run, which steals the lock, interleaves creates into the leg's diff window, and the leg's compensation then deletes banks it did not create (`createdInAttempt = post∖pre` absorbs the CLI's banks). The F-005 fix only closed driver-vs-driver theft; driver-vs-CLI theft at the shorter budget re-opens the exact hazard, despite idempotency-rerun's claim that "every provision-family writer serializes as one class".
