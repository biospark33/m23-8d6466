## Findings

- **F-A — LOW — residual of F-021: multi-model evidence is page-order sensitive between success and failure.** In `observeRefresh`, the first matching row that is terminal-failed returns `terminal-failure` immediately; a completed refresh for a *different* triggered model on the same bank never gets considered if the failed row is encountered first (`src/hindsight/nightly-consolidate.ts:466-471` — return-on-first-match across the row loop). With ≥2 triggered models where one refresh failed and another completed, the bank's outcome depends on row order in the operations page, not on recency or completeness. Beyond the story's shape (the provisioner creates exactly one MM per manager bank, deterministic id), but the fix made multi-model matching load-bearing, so the ordering semantics are now part of its contract. Suggested shape: scan all matching rows per poll; prefer an observed success, report terminal-failure only if none observed (or report the failure only when no other triggered model's refresh is in flight/completed).
- **F-B — LOW — spec-record gap: unrecorded non-add edits to M1.1/M2-owned files under an amendments section that declares the schema widen "THE sanctioned deviation."** `resolveProvisionedRepoBankId` body rewrite + `safeRepoBaseCandidates` export (`src/hindsight/bank-provisioner.ts`), `assertMentalModelId` + guard call in `patchMentalModel`, and the `offset` param on `listOperations` (`src/hindsight/client.ts`) each go beyond the adds-only enumeration in the story's Region-ownership note and DoD. Each is a correct, review-mandated fix (and the F-004 revert nets to pre-story behavior), but the pre-merge record is incomplete: a future auditor reading "THE sanctioned deviation" would conclude these were unsanctioned — the exact failure mode round 1 flagged (F-004, F-013). Suggested shape: one amendment line listing the round-1 fix-wave's non-add edits to M1.1/M2-owned surfaces and their review provenance.
- **F-C — LOW — wall-budget boundary band misattributes exhaustion to missing evidence.** A bank whose turn starts just before `wallDeadlineMs` runs with a near-zero effective window (`bankDeadlineMs = min(evidence, wall)`) and fails `REFRESH_EVIDENCE_MISSING` — a code whose remediation says "verify the instance fired the consolidation-trigger refresh" — when the true cause is budget exhaustion (`NIGHTLY_BUDGET_EXHAUSTED` exists precisely for that attribution and fires only for banks starting at/after the deadline). Fail-loud and exit-1 either way; the guard is real. Suggested shape: if `wallDeadlineMs - startOfBankTurn` is below one poll interval, emit `NIGHTLY_BUDGET_EXHAUSTED` for that bank too.
- **F-D — LOW (cosmetic) — stale schema comment in an unowned fixture.** `tests/swarmclaw/fixtures/fake-hindsight-mcp.ts:180` still says "The story's ConsolidateResponseSchema is {consolidatedCount, preservedCount, durationMs}" after F-025 tightened the schema to require `operation_id`. The MCP lane is not schema-parsed (verified: only `client.ts:446` and `nightly-consolidate.ts:357` parse it), so behavior is unaffected — but the comment now misdocuments the contract it cites. Suggested shape: one-line comment update or deletion of the citation.
