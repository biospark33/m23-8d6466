## Findings

### F1 — Trace worker_output seam proves content availability, not tool invocation (MEDIUM)
**AC/constraint:** AC3 (in-box recall leg), AC1's "in-box recall green" limb; the round-1 re-seam's claim.
**Evidence:** The task text embeds the marker verbatim — `Step 1: call the kg_recall tool exactly ONCE with bank "${base}" and query "${marker}"` (test:419-420). The primary assert is `payloadText(p).includes(round.marker)` → `expect(markerHits.length).toBeGreaterThan(0)` (test:679-689). `WorkerEnvelope.summary` is a fixed template (`Worker ${agentId} output`), so the hit must come from `output` — the redacted worker output (`team-event-adapter.ts:230-241`) — but a worker that never invoked kg_recall can still echo its query phrase into a fabricated `result.summary` and satisfy the seam. The channel that would prove the call directly (`[kg-recall]` stderr) is dead on success by the driver's own admission (test:625-629), so no artifact on a green round records `kg_recall.call`.
**Residual weakness, named honestly:** on a green round nothing distinguishes "the worker recalled the seeded memory" from "the worker quoted its own prompt". Failure mode is a false green when the extension is absent/refused AND the worker fabricates a compliant summary (models echo query strings; this is not exotic).
**Fix (one line):** assert a substring unique to the seeded memory TEXT, not the marker — e.g. `"seeds this observation for the"` (present only in the retained content, test:412-416), or seed a second memory reachable only via recall. The marker assert can stay as a weaker companion.

### F2 — AC2 degrade control exercises the seam function, not the dispatch call site (LOW)
**AC/constraint:** AC2 (negative-control limb "a timeout/unreachable-gateway dispatch that FAILS instead of proceeding unprimed").
**Evidence:** LD calls `primeDispatchBrief` directly with an injected dead `HindsightClient` (test:314-316). A regression at dispatch's call site (e.g. a wrapper that converts the never-throw seam into a dispatch failure) would not flip LD. Acceptable because the story forbids modifying dispatch (Files to Modify: run-completion "not modified" posture) and M1.2's evidence owns the verb path — but the negative control's reach is the seam function only. The positive limb does go through the real verb (L1), so a dispatch-side regression that broke priming would still surface there.

### F3 — DoD preflight "roster-check green before fire" is not wired (MEDIUM)
**AC/constraint:** Definition of Done — "Preflight: `bun scripts/roster-check.ts --roster config/rosters/memory-live.roster.yaml` green on the new roster file before fire (F097 precedent: roster-check is a pre-flight gate, not post-hoc)".
**Evidence:** No invocation of `scripts/roster-check.ts` anywhere in the round or the harness (grep: zero hits in both files; the file exists at `scripts/roster-check.ts`). The round substitutes: existence check (test:377-379), `git cat-file -e sha:config/rosters/memory-live.roster.yaml` pre-spend check (test:383-385), staged-copy byte-identity (test:458), and dispatch's own `parseRoster` of the staged roster (`dispatch.ts:1598ff`) — schema validation, not the roster-check gate (model pings / role-shape checks). An operator following only the round gets no roster-check gate; an invalid roster surfaces post-staging or on the box instead of pre-fire.

### F4 — AC7 volatile walk greps the query text but not the result content (LOW)
**AC/constraint:** AC7 ("volatile fields (recall query text, result content) appear in NO row").
**Evidence:** `volatile = [round.recallQuery, round.marker]` (test:824) — the same string twice, since `recallQuery = marker` (test:411). The seeded observation text — the "result content" the AC names — is never grepped against the rows. Rows are content-free by construction today (receipt detail `{documentId, bank}`, digest-only; run-retain payload has no prose), so no row is dirty; but the walk as written would not CATCH a future detail-field change that starts carrying content. Belt-and-braces gap, not a live violation.

### F5 — F10 hygiene check is vacuous on a green round (LOW)
**AC/constraint:** AC3 hygiene limb (explicitly hygiene-not-proof per the story, so no AC is violated).
**Evidence:** `hygiene: events.every((e) => e.event.rawControlChars !== true)` (test:635) evaluates over the `[kg-recall]` stderr scan results (test:611-618), which is empty on every green round (dead channel) — `every` on `[]` is `true`. The evidence field advertises a check that cannot fail. Harmless; worth a comment or dropping.

### F6 — Battery evidence is not its own leg JSON; the battery CLI is never exercised live (LOW)
**AC/constraint:** AC1/AC5 evidence shape; Observability Contract "one timestamped machine-checkable JSON per leg".
**Evidence:** The round calls `runNegativeProbeBattery` as a library (test:881-886); probe outcomes ride `m23-revoke-verified.json`'s `phases` array (test:887-900) rather than a distinct battery file, and `scripts/e2e/memory-negative-probes.ts`'s CLI (exit 0/1/2 contract, its own scrubbed evidence writer) runs only under `bun test` unit coverage, never against the live gateway. Leg-event vocabulary (`memory-live.probe.<name>`) is still present in the phases, and AC5's refusal verdict is round-failing either way — shape nit, not a coverage hole.

### F7 — Teardown leg's QDS_LOG_VERBOSE unmute is unnecessary (INFO)
**AC/constraint:** none (comment accuracy).
**Evidence:** The comment (test:762-765) claims the log sink mutes under `NODE_ENV=test` "which bun test sets and runFleet merges into this child", hence the unmute for the teardown verb. Verified: the mute (`src/swarmclaw/log.ts:29-31`) guards the DEFAULT sink and the embedded-caller path (`scripts/fleet.ts:2424`) — but the fleet CLI's `import.meta.main` block replaces the sink BEFORE `run()` with an unconditional fd-2 writer (`scripts/fleet.ts:6361-6364`, and the 2424 gate then sees a non-boot sink and skips). Every `runFleet` child therefore logs unmuted to stderr regardless. The env flag is harmless belt-and-braces — and its presence is what makes the divergent-alarm stderr assert's robustness not depend on this sink subtlety. No change needed; the comment's premise is wrong.
