# Edge Case Hunter — M1.2 round 1 (diff at `_bmad-output/reviews/m1-2-round1/diff.patch`)

- **[HIGH] In-box `kgContext` is rendered verbatim with NO re-validation of the workload-writable witness — the repo's own fixContext discipline ("the host validates once before dispatch; the engine validates AGAIN because what it reads is a FILE inside the checkout — a tree the run's own earlier code phases can rewrite", `src/phase-engine/phases/dispatch-task.ts:311-314`) is not applied to the new sibling channel.** `scripts/pipeline-run.ts:1622-1624` appends `brief.kgContext` on only `typeof === "string" && length > 0`, and `readResidentBriefSource` (`scripts/pipeline-run.ts:1412-1444`) does zero schema validation — no `BriefSchema` runs anywhere in-box (grep: only fixContext bounds are re-checked, in dispatch-task.ts). The ceiling/charset guard in `src/fleet/brief-schema.ts:319-320,336-343` executed only on the host at dispatch time, which is not transitive to the box-side read. Trigger: any code phase (or box workload) rewrites `run-context.json`'s `kgContext` to arbitrary size/content between dispatch and resident arming → unbounded, control-char-laden, forged `<kg_context>`/instruction text flows verbatim into the armed resident's prompt context (the steering 16k cap only bounds solicit calls and `truncateTailWithSuffix` drops the HEAD, so tail-injected blocks survive whole; the arming context is outside that cap). Consequence: prompt injection into the spending resident + token-spend blowup — the exact bug class DF6.1a's fail-closed recheck exists for. Guard sketch: re-run the kgContext bound+charset check (or the field-level schema) at the `readResidentBriefSource`/`residentContextLines` boundary, refusing or dropping the field fail-closed like fixContext.

- **[HIGH] Recall-row filename path traversal — the side channel writes `${runId}.json` with `runId` taken verbatim from the raw, pre-schema brief.** `src/hindsight/kg-context.ts:240-252` (`writeFileSync(join(base, \`${runId}.json\`))`) with `runId = briefStr(briefJson, "requestId")` at `src/hindsight/kg-context.ts:269`; `ingestBriefJson` (`scripts/fleet.ts:1318-1378`) primes the bare `JSON.parse` output before ANY verb schema validation, and the row is written even when the brief has no repoSlug (emit at `src/hindsight/kg-context.ts:314` precedes every bank call). Trigger: with the memory env configured, `fleet dispatch --brief` a file containing `{"requestId":"../../payload","repoSlug":"x/y"}` → `mkdirSync` + `writeFileSync` at `<cwd>/_bmad-output/memory/recall/../../payload.json`, i.e. an attacker-named `.json` overwrite outside the recall dir (row content partially attacker-influenced via runId echo and repoSlug-derived bank ids). Guard sketch: `if (!/^[A-Za-z0-9._-]+$/.test(runId) || runId.includes("..")) return;` in `writeRecallRow`.

- **[MEDIUM] Recalled bank content can make the primed brief fail its own charset gate, turning a v5 exit-0 dispatch into exit 2.** `buildKgContextXml` escapes only `&<>` (`src/hindsight/kg-context.ts:181-183`), so a recalled observation's text is embedded raw — including `\r`, `\x0b`, `\x0c`, `\x7f` — and `BriefSchema`'s `KG_CONTEXT_CONTROL_CLASS` (`src/fleet/brief-schema.ts:319-320`) then refuses the whole brief ("kgContext may not contain control characters…") at dispatch. The seam never round-trips its own assembly through the boundary it leans on. Trigger: any observation in the repo bank or `qds-collective` whose text carries a C0 char other than `\n`/`\t` (e.g. CRLF-authored or vertical-tab content retained by other tooling) + a dispatch for that repo. Consequence: dispatch exits 2 invalid-brief on briefs v5 accepted; repeated until the bank content is fixed. Guard sketch: strip or refuse offending observations in `recallFanOut`/assembly (charset-filter each observation before it enters the block).

- **[MEDIUM] `issueId` never reaches the recall query — the seam reads it as a string but the schema types it as a number.** `src/hindsight/kg-context.ts:322-324`: `briefStr(briefJson, "workId") ?? briefStr(briefJson, "issueId")` where `briefStr` requires `typeof v === "string"`, but `BriefSchema` declares `issueId: z.number().int().positive()` (`src/fleet/brief-schema.ts:358`). Trigger: any issue-driven dispatch (the primary workload) → `query = repoSlug` alone; every issue of a repo recalls the identical top-5 observations. Consequence: memory grounding is repo-grain, never issue-grain — the AC1 "same brief always recalls the same thing" contract silently degenerates for issue work. Guard sketch: `const id = briefStr(briefJson, "workId") ?? (typeof brief.issueId === "number" ? String(brief.issueId) : undefined);`

- **[MEDIUM] Live round: an L2 failure after bank seeding strands the resolver-fresh repo bank (with its seeded marker) permanently.** L2 pushes the created bank to `round.banksWeCreated` (`tests/fleet/e2e/memory-cycle.live.test.ts:489`) and its own finally deliberately does NO bank cleanup ("L3 owns them"), but L3's hollow-leg guard (`tests/fleet/e2e/memory-cycle.live.test.ts:631`) throws BEFORE its `try`, so L3's `finally` (bank deletion at :761) never runs when `runId`/`vmName` are `""`. Trigger: the L2 dispatch verb exits non-zero or times out after `createBank`+retain (its catch rethrows at the dispatch-verb phase) → L3 refuses to fire → cleanup unreachable. Consequence: the seeded `m12-prime-…` marker persists in a bank that every future real dispatch of `Quantum-Digital-Solutions/QDS-Factory` resolves to and recalls as grounded memory (and the leg's own discipline calls a stranded bank a real failure). Guard sketch: hoist the `banksWeCreated` deletion into L2's finally (or move L3's guard inside its try).

- **[MEDIUM] The new `kg-recall` stdout line can hijack runId scraping on the dispatch-failure path.** The seam's log entry carries a `runId` field (`src/hindsight/kg-context.ts:297-311`) and fires BEFORE dispatch's ack; the harness's `emittedRunId` takes the FIRST `"runId":"qds-…"` match in stdout+stderr (`tests/fleet/e2e/live-harness.ts:379-381`) and L2 arms `round.runId` from it before the exit-code assert (`memory-cycle.live.test.ts`, "Ownership armed BEFORE the assertion"). Trigger: a brief whose `requestId` matches `qds-\d{8}-[a-f0-9]{6}` (never validated at ingest) + a failing dispatch → the kg-recall line's id wins `emittedRunId` → L3 harvests/tears down a nonexistent name while the real box survives the finally (its destroyQuietly targets the wrong name). Guard sketch: key the log field `runId` only on the minted id, or have `emittedRunId` skip `operation:"kg-recall"` lines / take the LAST match.

- **[LOW] Row/record join silently broken for absent-or-invalid brief requestId.** Dispatch mints a fresh UUID when `resolveBriefRequestId` refuses the brief's value (`scripts/fleet.ts:2766`), but the seam keyed the row on the raw value (`src/hindsight/kg-context.ts:269`): absent → NO row and NO line (the M1.3 cycle counter misses the cycle entirely); invalid-but-present → row written under a filename no run record will ever carry. Trigger: dispatch a brief without `requestId` (dispatch proceeds fine, minted id) with memory env configured. Guard sketch: thread the verb's resolved requestId into the seam, or refuse row-writing unless the value round-trips through `resolveBriefRequestId`.

- **[LOW] Head-truncation evicts the founding context block — including `kgContext` and the citation instruction — once any directive folds.** `residentContextLines` appends `kgContext` LAST into `promptContext` (`scripts/pipeline-run.ts:1622-1624`); steering's `truncateTailWithSuffix` (`src/phase-engine/steering.ts:349-366`) drops the HEAD of the joined context when the 16k ceiling is crossed, and folded attach/directive text is PUSHED after the founding lines (`steering.ts:958`). Trigger: a near-8000-char kgContext + a single folded attach/directive (the attach budget alone is 8000) → the run identity lines AND the entire memory block ( appended at the founding block's tail) are cut while the newest directive text survives; the `[truncated, N chars total]` marker does not name what was lost. Consequence: memory grounding (and citations) silently vanish from every later solicitation. Guard sketch: reserve a founding-context floor in `truncateTailWithSuffix` callers, or emit a marker line when the kg block is evicted.

- **[LOW] `deriveDocumentId` throws a bare TypeError instead of `RunRetainError` for a non-string runId.** `src/hindsight/run-retain.ts:90-93` — the `typeof runId !== "string"` arm's message calls `runId.slice(0, 64)`, which itself throws on the non-string value the check just established. Trigger: a caller passing a non-string runId (the type lies only at runtime boundaries, e.g. a hand-edited record). Consequence: the best-effort catch in both twins masks it, so the skip line reports the TypeError text instead of the typed `retain-run-id-invalid` code. Guard sketch: `JSON.stringify(String(runId).slice(0, 64))`.

- **[LOW] The recall row path is keyed on requestId alone and written non-atomically.** `src/hindsight/kg-context.ts:240-252`: two briefs reusing one `requestId` (replayed brief dispatched twice, or dispatch+submit of the same file) concurrently `writeFileSync` the same `${requestId}.json` — no temp+rename — so a concurrent M1.3 reader can observe a torn row and the last writer silently erases the first dispatch's cycle row. Trigger: two concurrent ingests with the same requestId. Guard sketch: write `${runId}.${pid}-${Date.now()}.json` or temp+rename.

- **[LOW] The seam's never-throw contract depends on `log()` never throwing — including from inside the catch.** `src/hindsight/kg-context.ts:344-349`: the ladder-(b) catch itself calls `emitAndReturn` → the unguarded `log(...)` at :297-311 (`writeRecallRow` is guarded; `log` is not). The default sink swallows write errors (`src/swarmclaw/log.ts:29-37`), but any `setLogSink` callback that throws (redirected/JSONL file sinks, test-style sinks) makes `primeDispatchBrief` reject from within its own catch → `ingestBriefJson` rejects → the dispatch verb exits off the v5 table, the exact outcome AC2a/AC2b promise cannot happen. Trigger: memory env configured + a throwing sink + any ladder-(b) condition. Guard sketch: wrap the `log(...)` call in `emitAndReturn` in try/catch like `writeRecallRow`.
