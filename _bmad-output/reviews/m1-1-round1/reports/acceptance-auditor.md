## Findings

- **AC3 serialization uses a different lock than the one the AC names — the diff window is NOT serialized against the provisioner itself (concurrent `provisionBanks` / CLI runs).** Violates AC3: "the whole diff window is serialized: the pre-snapshot, `provisionBanks`, post-snapshot, and any compensation all run under the provisioning run lock (`acquireRunLock` on the provisioning state dir …), because a concurrent driver's creates landing inside this attempt's diff window would be misattributed to THIS attempt and deleted as its residue." Evidence: `scripts/p0-9/provision-and-import.ts` (diff L1793) `const lockPath = deps.lockPath ?? join(homedir(), ".hindsight", "provision-leg.lock");` plus (diff L1624) `noLock: true, // The leg's own lock … the provisioner's inner single-flight would deadlock on it.` — while the provisioner's own run lock is `~/.hindsight/provision.lock` (`src/hindsight/bank-provisioner.ts:126`). The plan (`.unlazy/m1-1/PLAN.md` C-compensation) records this as deliberate, but the shipped path only excludes the two leg drivers against each other: a concurrent `bun scripts/provision-hindsight-banks.ts` run (or any bare `provisionBanks` caller) holds `provision.lock`, invisible to `provision-leg.lock`, so its creates land inside the leg's diff and are deleted as this attempt's residue — exactly the misattribution the AC's clause exists to prevent. Holding `provision.lock` across the window while passing `noLock: true` would have satisfied the AC's named lock; the distinct-path choice weakens the guarantee the AC specifies.

- **AC3's rerun idempotency is met by substituting the second run — and the story's E2E-slice CLI demo ("run twice creates nothing new") is unsupported by the shipped CLI.** Violates AC3's letter: "When `provisionBanks` runs and then runs again, Then the roster … is identical after both runs" and the E2E slice: "`bun scripts/provision-hindsight-banks.ts` run twice creates nothing new on the second run." Evidence: the consumed resolver treats the factory's OWN base bank as a collision (`src/hindsight/bank-provisioner.ts:184-209`, `resolveRepoBankId`: `!existing.has(safeBase)` fails → `const candidate = \`${safeBase}-${n}\``), so a second `provisionBanks` run creates `qds-factory-2` + `qds-factory-2-dev-meta` junk. The drivers work around it by never re-running the resolver on a rerun (`scripts/p0-9/idempotency-rerun.ts`, diff L2091: `const roster = [base, \`${base}-dev-meta\`, COLLECTIVE_BANK_ID]; … await client.createBank(bankId);` with mode `reupsert-existing`) — so the leg proves the driver's rerun path, not "provisionBanks runs and then runs again". Meanwhile the CLI's dedicated lane still calls `provisionBanks` unconditionally (`scripts/provision-hindsight-banks.ts`, diff L222-230), so the E2E-slice demonstration executed exactly as written produces junk banks and a failed idempotency claim. The story simultaneously demands rerun-identical rosters and a consumed-unchanged provisioner — those two are contradictory in the consumed code; the resolution lives only inside the leg drivers and is recorded nowhere an operator following the E2E slice would see it. (Related: the story's Files-to-Modify letter for this script is "adds only — the v6a `qds-` roster args" — nothing roster-arg-shaped landed.)

- **AC3's rollback-path coverage requirement names the idempotency-rerun leg; that leg's test block has no rollback fixture.** Violates AC3: "The idempotency-rerun leg's coverage includes the rollback path — a fixture failure on a LATER create (e.g. bank 2 of 3) must show the earlier bank deleted, not merely assert the roster." Evidence: `tests/p0-9/legs.test.ts` `describe("idempotency-rerun", …)` (diff L4289-4325) contains exactly one test ("two runs: roster identical across three snapshots…") — the happy path only. The rollback fixture (create fails / delete fails → residue named) lives solely in the `provision-and-import` block (diff L4133-4166). The driver code implements compensation in `idempotencyWindow`, but per the AC's own sentence its coverage must include the rollback path, and it does not. (The DoD's rollback-test item is satisfied; the AC's leg-specific sentence is not.)

- **AC4's `dangerRetired` verdict counts ANY non-2xx as retirement — a bank-scope refusal (404/422 on the never-created probe bank) is indistinguishable from an auth refusal in the machine-readable verdict.** Violates AC4: "The check does not presuppose its result: if 0.10.0 refuses both, the … danger … is retired on this instance by evidence" — a refusal must be an AUTH refusal to be that evidence. Evidence: `scripts/p0-9/auth-retired-check.ts` never creates the probe bank (no `createBank` anywhere; the unauth retain POSTs straight to `${baseUrl}/v1/default/banks/${probeBankId}/memories`, diff L3266), and computes `const dangerRetired = unauthenticated.measured && !unauthenticated.answered;` (diff L3396) where `answered` is only `res.ok` (diff L3128: `kind: res.ok ? "answered" : "refused"`). If 0.10.0's retain requires an existing bank, a no-auth instance still refuses with 404/422 → `dangerRetired: true` — a false retirement verdict. Same conflation on probe (b): a 404 on the missing bank's profile is classified `known-key-out-of-scope-http_404` (diff L3327) — a missing-bank refusal recorded as an out-of-scope auth outcome. The status/body-tail are recorded (human-inspectable), but the boolean and class fields — the machine-checked parts — can over-claim. Distinguish refusal reasons (401/403 vs 404/422) or create the probe bank first.

- **AC1's "no host:port literal in driver code" is violated by the down-instance probe target in negative-probes.ts.** Violates AC1: "Every leg driver reads the env by name — no host:port literal in driver code." Evidence: `scripts/p0-9/negative-probes.ts` (diff L2624) `const PROBE_DOWN_DEFAULT = "http://127.0.0.1:9";` — the comment claims "the one sanctioned host:port literal in the P0.9 drivers (team-lead brief)", and the plan's letter excepts only "forbidden-origin trap literals", which port 9 is not. Intent is preserved (it is a probe TARGET that must not answer, never the instance origin, env-overridable via `QDS_PROBE_DOWN_URL`, and trap-checked), so this is a letter violation only — but either the story or the sanction should be recorded where the AC is enforced.

- **AC1's shape-check-before-downstream-consumption ordering is machine-enforced only on the round-trip leg; the other four legs consume the instance with no ordering gate.** Violates AC1's letter: "before any downstream leg consumes the instance, the hindsight-live leg ALSO runs ONE retain+recall response-shape check." Evidence: only `scripts/p0-9/round-trip-dedicated.ts` gates on prior live-stamped hindsight-live evidence (`scanLiveShapePrereq`, diff L2434-2441); `provision-and-import.ts`, `idempotency-rerun.ts`, `negative-probes.ts`, and `auth-retired-check.ts` contain no prereq check. The story's DoD narrows the ordering to "ran BEFORE the round-trip leg" (the schema-sensitive consumer), which is satisfied — flagging the AC-letter gap for the record, since VPS-day execution order of the other legs rests on operator discipline alone.

- **Provision-script additions exceed the dev-half contract's closed list and change shared-lane CLI behavior beyond it.** Deviates from plan C10 ("Provision script adds-only: `--no-bridge-probe` dedicated-topology flag + INV-MEM-1 qds- prefix guard; everything else byte-identical") and from the story's Files-to-Modify letter ("adds only — the v6a `qds-` roster args; stdio log sink unchanged"). Evidence: `scripts/provision-hindsight-banks.ts` additionally adds `checkHindsightBaseUrl()` (diff L122-135) enforced in `main()` for BOTH lanes (diff L194-204) — a new `base_url_required` exit-1 refusal on the pre-existing shared topology when `HINDSIGHT_BASE_URL` is unset, where the CLI previously proceeded on the client default. The guard serves INV-MEM-1/AC1's wrong-instance negative control and is adds-only with tests, but it is a behavior change to the shared lane outside both contracts' enumerated additions and is not recorded as a documented deviation the way the plan recorded leg-lib.ts (C13). Recommend recording it (story Dev Agent Record / contract table) or scoping it to the dedicated lane.

- **Observability contract inconsistency: three drivers emit `{event:"p0-9-leg"}` stderr lines but record `stderrTail: ""` in their evidence JSON.** Tension with the Observability Contract: "Leg drivers log `{event:"p0-9-leg", …}` and write their own machine-checked JSON (`exitCode/stdoutTail/stderrTail` + structured fields)." Evidence: `scripts/p0-9/round-trip-dedicated.ts`, `scripts/p0-9/negative-probes.ts`, `scripts/p0-9/auth-retired-check.ts` all return `stderrTail: ""` (e.g. diff L2971, L3246-3248 regions) while calling `legLog(…)`; `hindsight-live.ts` and `provision-and-import.ts` capture their lines (`stderrTail: maskTail(logLines.join("\n"), { maxLen: 4000 })`, diff L927). The fields exist so the letter holds, but the closure-plan house style (`stdoutTail/stderrTail` payloads) is only half-honored and inconsistent across the six drivers — the emitted lines survive only on the process stderr, not in the machine-checked artifact.

- **legs.test.ts writes a live-stamped fixture into the real closure evidence dir (finally-cleaned).** Tension with the mock/live evidence-directory policy (AC2 negative control) and INV-MEM-4. Evidence: `tests/p0-9/legs.test.ts` "writeLegEvidence: live default = closure dir" (diff L3860-3878) writes `mode:"live"` fixture `…-p0-9-test-fixture….json` into `_bmad-output/evidence/p0-9-closure/` and removes it in `finally`. The slug can never satisfy round-trip's `-p0-9-hindsight-live` prereq scan and cleanup is forced, but a crashed run strands a fabricated "live" file inside the dir that means "live VPS-day evidence". Safer: point the live-default assertion at a temp dir via the repo-root-relative computation it already performs, or assert the path without writing.
