## F1 (HIGH) — Round-2 patch "writeP09 `at` shadow rename" does not hold: fixture silently drops `writtenAt`, making the writtenAt-wins test vacuous

`tests/memory/probe-harness.test.ts:148` (inside `writeP09`):

```ts
writtenAt: at,
```

`at` here is **not** the `stamp` parameter — it is the module-scope helper `function at<T>(arr: T[], i: number): T` (line ~121). This is the classic incomplete-rename: the parameter was renamed `at` → `stamp` (the filename template now correctly uses `${stamp.replaceAll(...)}`), but the `writtenAt:` reference was missed and now binds the helper **function**.

Consequence chain:

1. `JSON.stringify` omits function-valued properties — every P0.9 fixture JSON written by `writeP09` has **no `writtenAt` field at all**.
2. `loadP09MintRecords` (chunk A) reads `writtenAt` as `""` → `Date.parse("")` → `NaN` → epoch `Number.NEGATIVE_INFINITY` for **every** fixture record.
3. The test "loadP09MintRecords: latest writtenAt wins per bank" therefore resolves through the F-015 **filename tie-break** (`epoch === prev.ts && name > prev.name`, −Inf === −Inf), never through the `Date.parse` epoch comparison. Same for "ignores ok:false records" (that one still genuinely tests `ok` filtering, since the ok:false file never enters the winner loop at all).

Result: the F-015 epoch-ordering logic — patched in round 1 ("writtenAt Date.parse ordering with tie fallback"), re-affirmed in round 2 ("writtenAt tie-break comment honesty") — has **zero effective test coverage**, and nothing fails: tsc is clean (function value in an untyped object literal), biome is clean (`stamp` is still used for the filename), and all tests pass for the wrong reason. The story record's round-2 entry `- [x] [Review][Patch] writeP09 'at' shadow rename [tests/memory/probe-harness.test.ts]` is false against this tree.

Fix is one line (`writtenAt: stamp,`); both affected tests stay green and become meaningful. Note that after fixing, the "latest wins" test exercises only the epoch path — keep one deliberate same-stamp case if the tie-break itself is to stay covered.
