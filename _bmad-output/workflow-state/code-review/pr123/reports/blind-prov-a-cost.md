# Blind Hunter — chunk-prov-a + chunk-cost

Scope reviewed: `src/providers/run-record.ts`, `credentials.ts`, `timeout.ts`, `budget-gate.ts`, `reaper.ts`, `index.ts`, `src/providers/cost-ledger.ts`, `scripts/qds-cost.ts`, `scripts/cap-hit-demo.ts`. Diffs judged alone; line numbers are best-effort new-file positions from hunk headers.

---

**[HIGH] Transient record-read fault past the grace window expires a LIVE run's reservation (fail-open on the money path)**
- `src/providers/cost-ledger.ts:~1385-1400` (admitIssue transaction loop, the `catch` arm around `readRunRecord`)
- Trigger: run R is admitted and its box/key are live. More than `ADMISSION_GRACE_MS + ADMISSION_SKEW_MARGIN_MS` (6 min) later, R's record file is momentarily unreadable — EIO on a failing mount, EACCES after a permission change, a stale NFS handle — exactly when another dispatch for the same issue runs `admitIssue`. The catch arm treats "cannot be read at all" as "this run will never report spend", `continue`s, and drops R's full ceiling from `reservedMicroUsd`. The concurrent dispatch is then granted R's entire headroom on top of R's live exposure; both runs spend, the cap is exceeded. The 6-minute young-guard protects only the first minutes of a run's life; a long-lived live run gets zero protection against a transient fault at the sampling instant. The comment argues "a throw past the cutoff expires the reservation too" avoids a wedge, but it trades a recoverable refusal for an unrecoverable overspend — the direction INV-COST-6 everywhere else forbids. Aged+throw should distinguish errno (EIO/EACCES ⇒ keep counting/refuse) from structural corruption, or at minimum never expire a record that statSync shows exists and is non-empty.

**[MEDIUM] Reaper's shared ownership predicate strands legacy caller-supplied-id boxes as permanently billable**
- `src/providers/reaper.ts:~377-385` (sweep VM classification) and `~631` (ownership recheck), via `isFactoryOwnedVm` / `RUN_ID_SHAPE`
- Trigger: the diff itself states `create()` historically took caller-supplied ids, so records with ids like `trailing-` exist by construction from earlier builds — that is the entire justification for `LEGACY_RUN_ID_RE` on the read/write paths. But the reaper's ownership test stayed on the STRICT `RUN_ID_SHAPE` (`<slug>-<YYYYMMDD>-<6hex>`). A factory-owned, correctly tagged box named with a legacy id classifies as `foreign` → `action: "report"`, never destroyed by either reaper. The record side got a legacy accommodation specifically so such runs stay closable/tearable-down; the box side got none, so the one artifact that keeps billing is the one the sweep will never reclaim. Run-record read paths were loosened to prevent exactly this "keeps billing with no route to reclaim it" outcome; the driver-side gate reintroduces it through the name door.

**[MEDIUM] Close→price race guard is a fixed 6-minute wall-clock bet; a slower recovery re-grants headroom the late box-hours charge then exceeds**
- `src/providers/cost-ledger.ts:~1400-1415` (closed-record retirement, `closedAtMs <= graceCutoff`)
- Trigger: teardown closes the record at T, then crashes before ingesting the priced `box_hours` row. Recovery (host reboot, operator intervention, CI queue) takes longer than `ADMISSION_GRACE_MS + ADMISSION_SKEW_MARGIN_MS`. At T+7min a new dispatch sees a closed record older than the cutoff, retires the reservation, and is granted the freed headroom; the recovery re-run then lands the box-hours row for the closed run, pushing cumulative spend past the cap. Box hours is documented as "the one term no key bounds", so nothing else absorbs the overshoot. The guard is sound only under the assumption that teardown's retry path always completes (or fails loudly) within 6 minutes of the close — an assumption nothing in the diff enforces. Cheap hardening: retire on close-age only when the run's teardown outcome is observable, or scale the cutoff off the record's teardown/error state.

**[MEDIUM] credentials.ts error-reporting paths invoke `redactSecrets` unguarded, and feed it non-string values**
- `src/providers/credentials.ts:~186-190` (`timed` catch), `~266-272` (mint compensation), `~555-562` (delivery compensation)
- Trigger 1: a step rejects with a pathological body that makes the redactor throw (the cap-hit-demo diff states outright that redaction in this family is fail-closed and *will* throw — that is why `safeRedact` exists there). In `timed`'s catch the `redactSecrets(...)` call sits before the original error is rethrown, so a redaction throw REPLACES the real credential failure with a redaction error — the operator debugs the wrong fault, and the compensation arms likewise swap a revocation-failure signal for a redaction crash.
- Trigger 2: `(e ?? {})` normalizes null/undefined rejections, leaving `err.message` undefined, so the fallback passes the raw rejection value — `null`/`undefined`/an object — into `redactSecrets(string, string)`. Whatever the redactor does with a non-string (throw, or stringify to `"null"`/`"[object Object]"`), the log line is wrong and the throw case cascades into Trigger 1. The demo wraps every call site in try/catch-to-marker; credentials.ts, the production sink for the same error text, does not.

**[LOW] Slug column-side fold is `lower()` only — no trim — so legacy rows stored with padded raw slugs drop out of every spend SUM**
- `src/providers/cost-ledger.ts:~95-100` (`issueScopeSql`), vs `sqlCanonicalIssueId` (~60-90) which trims
- Trigger: pre-canonicalisation inserts bound `ctx.repoSlug` RAW (visible in the removed lines of the ingest hunks). A historical row stored as `"Owner/Repo "` (trailing space from a hand-built brief) matches neither `lower(repo_slug) = ?` nor any canonical form, because the bind side canonicalises (trims) but the column side only lowercases. Its spend vanishes from `spentRow.total` — a silent under-count, the cap-bypass direction. The issue-id half of the predicate got a full column-side mirror including trim; the slug half stopped at case. The docstring narrows this honestly for issue ids (U+00A0) but does not acknowledge the ASCII-whitespace gap on the slug side.

**[LOW] qds-cost restates the records-dir resolution chain instead of calling `resolveRunsDir`**
- `scripts/qds-cost.ts:~213-216` (`const storeDir = dir ?? process.env.QDS_RUNS_DIR ?? DEFAULT_RUNS_DIR`)
- Trigger: `run-record.ts` exports `resolveRunsDir` with a docstring saying a second copy of the chain "resolves to a DIFFERENT directory the moment either end moves — a different ledger and a different record set". **[LOW] qds-cost's existsSync→open race can materialize an empty ledger and report a confident zero spend**
- `scripts/qds-cost.ts:~240-250`
- Trigger: `existsSync(ledgerPath)` returns true; the file (or its directory) is removed/moved before `new CostLedger(...)` opens it; SQLite creates a fresh empty DB; `readIssueCost` sums nothing and the CLI prints a real-looking zero-spend view with exit 0 for an issue that has burned budget. The comment acknowledges the race ("C5 notes: existsSync()-then-open race exists") and keeps the pre-check anyway, but on a reporting surface whose stated purpose is refusing to "read as 'nothing spent'", the known race defeats exactly that guarantee. Opening with a read-only/no-create flag would close it.

**[LOW] Same-pid lock theft after the 60-second grace can steal a live sibling thread's claim**
- `src/providers/run-record.ts:~1355-1370` (`stealIfOwnerGone`, the `raw !== body && !olderThan(lock, OWN_LOCK_GRACE_MS)` arm)
- Trigger: two worker threads share a pid; thread B enters a slow `fn()` (large record, slow FS, a debugger pause, SIGSTOP) lasting >60s. Thread A's `set()` on the same runId waits out `LOCK_TIMEOUT_MS`... no — A's steal path finds `owner === process.pid`, `raw !== body`, mtime older than `OWN_LOCK_GRACE_MS`, and takes B's live lock aside and deletes it. A third contender then claims the path and both mutate concurrently — the lost update the lock exists to prevent. Documented as a deliberate wedge-breaker ("wedged by some other means anyway"), but a debugger breakpoint or SIGSTOP past 60s is an ordinary developer scenario, not exotic breakage, and it converts a hang into silent data loss.

**[LOW] Put-back failure in the steal path vacates the lock path for EVERY contender, not just the failing one**
- `src/providers/run-record.ts:~1440-1455` (`stealIfOwnerGone` tail) / `putBack` (~1680)
- Trigger: a steal takes a foreign (live writer's) body aside and `linkSync` fails with ENOSPC/EMLINK/EDQUOT/EIO. The bytes are parked and THIS contender returns HELD, but the lock path is now empty while the live writer is still inside `fn()` — the next `claimLock` from any process succeeds immediately and overlaps the writer. The code logs `lock.not-restored` and relies on an operator restoring the parked bytes by hand; until then the record's mutual exclusion is simply off, with no mechanism (no flock fallback, no refuse-all flag) to keep other contenders out.

**[LOW] `cleanStaleTemps`'s 60-second same-pid rule deletes a paused sibling's in-flight write temp**
- `src/providers/run-record.ts:~905-918` (`cleanStaleTemps`, `owner === process.pid ? !olderThan(full, OWN_TEMP_GRACE_MS) : ...`)
- Trigger: a worker thread writes its temp, then stalls >60s before the rename (debugger, SIGSTOP, GC pause on a huge serialize). Another store construction in the same process sweeps the temp as leftover; the stalled thread's `renameSync` then fails ENOENT and a committed-in-intent mutation aborts after the caller's real work (provider calls) already happened. The write-and-rename window is microseconds in normal operation, so this only bites paused processes — same family as the lock-grace item above.

**[LOW] `--dir=` (empty value) is accepted and yields an empty records directory for the whole resolution**
- `scripts/qds-cost.ts:~190-200` (tokenize/parseValueFlags + `storeDir`)
- Trigger: `qds-cost owner/repo#1 --dir=` — if the shared arg parser permits an empty value (its source is not in these chunks), `dir` becomes `""`, which is not nullish, so the `?? env ?? default` chain stops at the empty string. `costLedgerOpts("")` then derives ledger/config paths off an empty base; the ledger pre-check most likely exits 1 `ledger-missing` (fail-closed luck), but the config half may resolve somewhere unintended first. An empty `--dir` value should be refused at parse time like a missing one.

**[LOW] Fresh create retry within the 5-second tombstone grace gets a raw EEXIST**
- `src/providers/run-record.ts:~1770-1790` (`clearCreateTombstone`, `CREATE_TOMBSTONE_GRACE_MS`)
- Trigger: a create is killed between `openSync(wx)` and the write, leaving the zero-byte tombstone. A retry dispatched immediately (automated retry loop, not a human) hits `size === 0` but `!olderThan(p, 5_000)` → returns false → the original EEXIST propagates. Every retry inside the 5-second window fails, so the fastest recovery path — retry — is precisely the one disabled for the grace duration. Correctness is fine; the availability blip sits directly on the crash-recovery path the tombstone machinery exists to serve.
