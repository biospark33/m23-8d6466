### Intentional behavior changes (round 7) — for the wave-2 fixer

1. **S3-1**: a signal landing mid-post_gate_failure-solicitation now unwinds the phase immediately (the authorized retry is NOT respawned); previously one zombie attempt could run and write a phantom `gate_fail` row. Any test pinning "solicitation resolves proceed → retry runs even though the signal landed during the solicit" would need to expect the immediate unwind instead (no such test observed in the 43 passing).
2. **S3-2**: `phaseIds` advertised to steering is now dispatch_task phase names only. A select_roster naming a code/engineer/agent phase is engine-REJECTED (directivesRejected +1 + tripwire) instead of accepted-then-never-consumed; if such a directive were ever returned accepted, the wiring layer now traces `residentRosterChoice {applied:false, reason:"rejected at the wiring layer — …"}` and banks nothing. Tests asserting acceptance of a code-phase pick, or asserting the never-consumed trace for one, need re-pinning.
3. **S3-7**: a manifest with duplicate dispatch_task phase names now gets roster steering disabled (empty advertised sets → all picks rejected + tripwired) and a new stderr event `resident_roster_steering_disabled`; the resident still arms and the run still settles. Tests using dup-named dispatch_task manifests with roster picks need re-pinning.
4. **S3-5**: the credential-scan depth cap now charges once per container (array or object) and pure nested-array chains are now actually refused at depth >32 (previously they recursed unchecked to a RangeError). The refusal boundary for object nesting is unchanged. A test nesting >32 pure arrays now gets the clean refusal message instead of a RangeError.
5. **S3-3**: the journal's resident block is refreshed once more (right after `run.finish`, before the run_end solicitation) — a marker-time read during the run_end window now sees real counts instead of the zeroed seed. Closed key set unchanged.
6. **S3-4**: a thrown `steering.solicit` now emits a `resident_solicit` line with `level:"warn"`, `accepted:false`, and an `error` field (new field on that event, additive).
