# Acceptance Audit — DF3.3 Resident Orchestrator Agent (PR 135)

Auditor: acceptance pass against `stories/df3-3-resident-orchestrator-agent.md` (AC1–AC5, Technical Notes, INV-RES-1..5, DoD) over chunks `chunk-engine-src.diff`, `chunk-fleet-src.diff`, `chunk-pipeline.diff`, with spot checks against `src/phase-engine/journal.ts`, `src/phase-engine/types.ts`, `scripts/lib/cli-args.ts`.

## Findings

- [MEDIUM] **`steeringIterations` inflated by a `retry` reply at the run-end point** — violates AC5 (per-phase `steeringIterations` telemetry) and Technical Notes point 3 ("run end … report text only"). Evidence: `chunk-pipeline.diff:827` passes `phase: outcomes[last].name` into the run_end solicitation, and `chunk-engine-src.diff:424-426` increments `steeringIterations[ctx.phase]` for any accepted `retry` whenever `ctx.phase` is set. Trigger: resident answers `{"action":"retry","guidance":"…"}` at run_end → `steeringIterations[<lastPhase>] += 1` although no retry is authorized or executed, and the directive is then dropped. This corrupts exactly the field the mandatory e2e demo uses as its steering proof (`steeringIterations.build == 1`). The recorded deferral "accepted-but-inapplicable directives counted" covers the `directives` count, not this per-phase counter.

- [LOW] **Claimed successor seam comments inside `solicit` do not exist** — Dev Agent Record states "Successor slots are named seam comments inside `solicit` (DF3.6 bounds → DF3.4 drain → render → call → parse → DF3.4 ack)". The shipped `solicit` (`chunk-engine-src.diff:372-429`) contains no such named seams; only the `promptContext` mutable comment (`chunk-engine-src.diff:189`) marks a DF3.4 slot. Spec constraint: Technical Notes "Shared file with DF3.4 and DF3.6" requires each successor to add only at defined points; DF3.6's `checkBounds(point)` wrap location is unmarked. Record-vs-code mismatch; the add-only contract itself is not violated yet.

- [LOW] **Credential-shaped brief refusal is gated on arming** — INV-RES-3 / DoD-Security: "a value matching a credential shape … refuses the run." `assertNoResidentCredentials` runs only inside `if (residentArmed && residentBrief !== undefined)` (`chunk-pipeline.diff:655-665`), and arming requires an identity field (`requestId`/`repoSlug`/`issueId`/`issueUrl`, `chunk-pipeline.diff:635-640`). Trigger: a witness brief containing `{"api_key": "sk-…"}` and no identity field neither refuses the run nor logs anything — it silently degrades to `status:"disabled"`. No leak results (an unarmed brief never reaches a prompt), hence LOW.

- [LOW] **AC2 tripwire omits the rejected action name for the unknown-field case** — AC2: the `residentTripwire` row records `cause:"gate_bypass_attempt"` "with the rejected action name." `rejectionDetail` (`chunk-engine-src.diff:316-322`) returns `unrecognized action: <name>` only when the action is outside the union; for a known action carrying an unknown field (equally in AC2's trigger list) the detail is the first zod issue (`formatZodIssue`), which names the offending key, not the action. Trigger: `{"action":"proceed","foo":1}` → detail like `Unrecognized key(s) in object: 'foo'`; the action name "proceed" is absent from the row.

- [LOW] **Accepted directives at run_start/run_end leave no record beyond a count** — AC1: "the resident appears in the journal only as recorded directives, guidance text, and telemetry." post_gate_failure `abort`/`retry` directives get `resident_directive` trace rows (`chunk-pipeline.diff:417-434, 444-461`), but an accepted run_start `select_roster` and any run_end directive (including the "report text only" `note`) are neither traced nor journaled — only `telemetry.directives` moves and the raw reply artifact persists (`chunk-pipeline.diff:743-754, 823-831`). Trigger: resident's run-end report note exists only in the persist-dir artifact, not in the journal or trace store the evaluation reads.

- [LOW] **Best-effort reply persistence can let an accepted directive execute with no persisted raw reply** — Observability Contract / DoD-Security (v5 §5.2): "Every rendered prompt and raw reply persists pre-execution, redacted." Reply persistence is wrapped in try/catch and downgraded to a stderr line (`chunk-fleet-src.diff:308-323`); on write failure the reply still flows to `solicit`, where it can be parsed, accepted, and acted on. This trade-off is recorded in the story's round-2 patch ledger, but the §5.2 contract text ("every … persists") stands unamended — the code now implements a weaker guarantee than the spec sentence.

- [LOW] **`resident.ts` header claims barrel import; code imports the module directly** — the file docstring says fleet "imports the engine barrel's steering port," but the import is `../phase-engine/steering.ts` (`chunk-fleet-src.diff:43`), bypassing `src/phase-engine/index.ts`. INV-RES-1's actual boundary (engine never imports fleet) is honored; comment-only inaccuracy.
