### LOW Artifact name allows newline but path validation rejects it
- File: src/phase-engine/phases/dispatch-task.ts:766-773
- Trigger: Malicious runner emits artifact with newline in name
- Detail: Line 767-770 rejects control characters C0 (`\x00-\x1f` EXCEPT tab) EXPLICITLY, then checks for newline separately. The regex `/[\x00-\x08\x0b\x0c\x0e-\x1f]/` EXcludes `\x09` (tab), `\x0a` (newline), `\x0d` (carriage return). So newlines are allowed through the control-char check. Line 767 then explicitly `artifact.name.includes("\n")` to reject newlines. This is correct behavior but the double-check suggests the regex could have included `\x0a` directly. The current implementation works but is redundant. Fix: consolidate by including `\x0a` and `\x0d` in the control-char regex, or add a comment explaining why they're separate (e.g., "newlines rejected with explicit check for clearer error message").
