## Section 2 — Findings

**F1 | MEDIUM | Caller-invented `runId` is validated by shape, not provenance** — `src/fleet/dispatch.ts` (`MINTED_RUN_ID_RE`, s-dispatch-02:148-158). Spec (AC2 / Technical Note "runId minting stays dispatcher-owned"): "a caller-invented `runId` (one never returned by `mintRunId()`) is rejected." Code: the `MintedRunId` brand rejects compile-time literals, and the runtime check re-validates the `qds-YYYYMMDD-hex6` shape and store grammar — but a runtime-built id of correct shape that was never emitted by `mintRunId()` and doesn't collide with an existing record is accepted. Mitigations: the CLI exposes no runId flag (dispatch positionals refused), and DF3.2 is the sole in-process caller, so the practical attack surface is a misbehaving in-process caller. A process-local minted-id registry in `mintRunId()` would close it. Not a false "done" claim — the diff's own comment concedes the brand "cannot see" runtime ids — but strictly weaker than the AC text.

**F2 | LOW | Stamped ceiling can be lower than the value handed to the mint** — `src/fleet/dispatch.ts` (`mintedCeilingMicros`, s-dispatch-02:765-777). Spec AC9b: run context carries "the same value dispatch hands DF2.3's mint … never re-derived downstream." Code stamps `min(admitted, mint-persisted-limit)` so an under-minting provider yields a manifest/run-context figure different from (never above) the mint request. Downward-only, and the deviation is recorded in the story itself (round 6, story:1172 — over-mint logs `mint-cap-over-request`). Safer than spec; listed because the AC text was never amended to match.

**F3 | LOW | "Mutates nothing" on unknown-runId verbs has a bootstrap residual** — `scripts/fleet.ts:241-253, 1190`. Spec AC4: unknown runId → exit 4 "mutates nothing." Code refuses a named `--dir` that doesn't exist and uses a read-mode store for `status`, but `harvest`/`teardown` still construct a writable store (mkdir+chmod 0700) against the default `.sandbox/runs` before the record probe, and any *existing* named `--dir` is chmod'd by the store constructor. The CLI's own comment names this residual and defers the fix to a no-create/no-chmod store mode. Record writes and driver calls: none — the core of the AC holds.

**F4 | LOW | Post-mint refusals log a runId, not `null`** — `src/fleet/dispatch.ts` (`refuse`, s-dispatch-01:798). Spec observability: "a rejected dispatch logs `runId: null` because no run was minted." Pre-mint rejections (schema, admission) log `null`; refusals after step 4 (e.g. `no-headroom`, `provision-failed`) log the minted id. The spec's rationale ("no run was minted") doesn't apply there — the id exists and is the operator's only handle — so this reads as rationale-conformant, but the literal sentence only holds for pre-mint rejections.

**F5 | LOW | Scope additions beyond the story's FRs (all defensive, mostly story-recorded)** — roster pre-admission validation (`roster-missing`/`roster-path-unsafe`/`roster-rejected`, s-dispatch-02:46-141; story round 4/6, story:982, 1311, 1601); SIGINT/SIGTERM handlers with exits 130/143 outside the 0-6 table (s-fleetcli:916-951; story round 9, story:1622-1623); `--no-harvest` passthrough; brief-single-source guard (`assertOneBriefSource`); EPIPE/EAGAIN output machinery feeding exit 6 (`stdout-truncated`, `completion-unwritable`); `key-unattributable` → exit 6 on teardown (story:1532-1534 records the exit-6 family extension for dispatch; the teardown key case rides the same "landed, needs an operator" classification); `assertDriverChosen` making `--driver` required on every verb (stronger than the E2E slice's bare `fleet teardown <runId>` wording, justified in `verbs.ts` header and preventing silent fake-driver destruction). None contradict an AC; none undisclosed — but a reader diffing story-FRs against the diff will see materially more behavior than the FR list names.

**F6 | LOW | Admitted-flag CLI-unreachability is covered by composition, not a dedicated test** — DoD: "a coverage test asserts no CLI flag or argv path can set [admitted]." There is no test grepping for `--admitted` (checked `tests/fleet/cli.test.ts` — zero hits). Unreachability holds structurally: the flag grammar is derived from `listVerbs()` (which declares no such flag), `parseArgv` refuses undeclared flags, and `verbs.test.ts` pins exact per-verb flag sets — so an `--admitted` argv cannot parse. The DoD's literal "a coverage test" for this specific property is satisfied only by that composition.

**Summary:** No CRITICAL or HIGH findings. Every AC and DoD item is present in the PR diff with evidence; the two PARTIAL/soft spots are F1 (runId provenance is shape-level at runtime — the only place the implementation is arguably weaker than spec) and a set of LOW documented deviations where the code is stricter than the story text and the story's review-round history, not the AC text, is where the amendment lives. Scope is, if anything, larger than the FR list — consistently in the fail-closed direction the story's invariants demand.
