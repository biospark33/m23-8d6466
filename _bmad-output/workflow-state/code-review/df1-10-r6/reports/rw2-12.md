## Findings

1. `LOW | SOURCE_PATHS stray-check's directory clauses bless non-image-input files — weaker than the invariant its docblock claims | tests/scripts/build-exedev-image.test.ts:1247-1250`

   Evidence:
   ```ts
   const stray = sourcePaths().filter(
     (p) => !EXEMPT.includes(p) && !sources.some((s) => s === p || s.startsWith(`${p}/`) || p.startsWith(`${s}/`)),
   );
   expect(stray, "a SOURCE_PATH that moves the image's recorded revision without being an image input").toEqual([]);
   ```

   Why real (traced): the predicate accepts a SOURCE_PATHS entry that is an *ancestor* of a COPY source (`s.startsWith(p + "/")`) or a *strict subfile* of one (`p.startsWith(s + "/")`), so it cannot see non-image-input files hiding inside a partially-COPY'd directory. That is exactly the failure this describe block was written to catch — its own docblock: "editing scripts/fleet.ts — not an image byte, not a buildId input — moved `src_sha` … A forced re-pin with an UNCHANGED buildId". There is one live instance: SOURCE_PATHS contains `oci/exedev` (publish-exedev-image.yml:507), under which sits `oci/exedev/binary-licenses.json`. Executed against the production functions on the post-PR tree: `copyContextSources(REAL_DOCKERFILE)` returns 17 sources, none covering `oci/exedev/binary-licenses.json`; `buildIdFileInputs` hashes 76 inputs and does not include it; nothing in the Dockerfile COPYs it (the NOTICE it feeds is a host-side artifact, not an image layer). Yet `git log -- oci/exedev …` sees it, so a licence-table-only edit moves `src_sha` → QDS_GIT_SHA/SOURCE_DATE_EPOCH → the digest (the marker is a layer) → pin-gate failure → forced re-pin with an UNCHANGED buildId — the exact "case worth reading twice" the gate's failure text warns about, and the exact state this test claims to prevent. (Every other directory-valued SOURCE_PATH — `src/fleet`, `src/lib`, `src/phase-engine`, `cli-anything/src`, `cli-anything/scripts`, `scripts/lib` — is COPY'd *whole*, so for those the ancestor clause is sound; `oci/exedev` is the only partially-covered one. The subfile clause has no live entry and would additionally mask under-coverage — a SOURCE_PATH naming one file under a COPY'd dir while sibling edits change image bytes without moving `src_sha` — though the sibling "covered by BOTH lists" test catches the gross form of that.)

   Minimal fix: drop the `p.startsWith(\`${s}/\`)` clause (no live entry needs it) and replace the ancestor clause with an explicit, argued allowlist (same pattern as `EXEMPT`) for directory entries that are COPY'd whole; `oci/exedev` then fails until SOURCE_PATHS narrows it to `oci/exedev/systemd` + `oci/exedev/Dockerfile` (both are buildId inputs) — or until `oci/exedev/binary-licenses.json` is added to the argued exceptions if directory granularity is deliberately kept.
