1. MED | P40 race survives its own fix: loser's `renameSync` throws ENOTEMPTY outside the cleanup try, leaking the whole `.partial-<uuid>` tree and recording a false permanent artifacts-loss | src/providers/harvest.ts:1635-1636 | `rmSync(destDir, { recursive: true, force: true }); renameSync(partial, destDir);` — the unique-`partial` fix (P40) documents "Each racer now extracts into its own tree and **the last rename wins with one complete, valid archive**" for "an operator teardown racing a reaper sweep". That pair of racers is two *processes*, and across processes the rm→rename pair interleaves: P1.rm(dest) → P2.rm(dest) → P1.rename (ok) → P2.rename. POSIX rename(2) over an existing **non-empty** directory fails with ENOTEMPTY, so P2's rename throws a raw Error. Traced consequences: (a) the throw is *outside* the `try { await streamTar(...) } catch { rmBestEffort(partial) }` (harvest.ts:1629-1634), so P2's fully-extracted `destDir.partial-<uuid>` tree — up to the 512 MiB cap — is leaked in runsDir with no cleanup arm anywhere (the pull's own `finally` removes only the staging tgz and legacy name, harvest.ts:1168-1171); (b) the error propagates through `timedStep` → `runArtifactsStep`'s catch (teardown.ts:251-326), which logs `teardown.artifacts_failed` with code "ENOTEMPTY" and writes `extensions.teardown.artifactsCode` — `fleet status` then reports "torn down, artifacts lost" (src/fleet/status.ts:967-982 renders any non-empty code as loss) **permanently**, because teardown then destroys the box, so no later successful pull can clear it (P43's clear only runs on a success that can no longer happen) — while P1's complete, valid archive sits at `dest`. Within one process the rm+rename pair is safe (synchronous, no await between), so this is exactly and only the cross-process race P40 was written to close; the invariant its comment claims is false for the losing interleave. | Wrap the terminal swap so every failure cleans its partial and a lost rename retries once: `rmSync(destDir, { recursive: true, force: true }); try { renameSync(partial, destDir); } catch (e) { if ((e as NodeJS.ErrnoException).code !== "ENOTEMPTY" && (e as NodeJS.ErrnoException).code !== "EEXIST") { rmBestEffort(partial, { recursive: true }); throw e; } rmSync(destDir, { recursive: true, force: true }); renameSync(partial, destDir); }` — i.e. rm+rename-with-one-retry, with `rmBestEffort(partial)` on any terminal failure so no racer leaks its tree.
