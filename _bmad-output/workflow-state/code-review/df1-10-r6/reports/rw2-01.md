## Findings

### 1. MED | Budget audit prices `destroyQuietly` at "1 control rm at 120 s" — the code's own worst case is 5 control ops (600 s), and the same under-pricing rides inside `fleetLeftovers`'s destroy pass | tests/fleet/e2e/tier2-in-box-engine.live.test.ts:1949-1951

Evidence (audit lines):

```
//   destroyQuietly     1 control rm at 120                              120 s
//   fleetLeftovers     5 × (control ls 120 + 8 s wait) + its destroy
//                      pass + the confirming re-list                    880 s
```

Production code actually executed (`src/providers/exedev/driver.ts:1198-1215`):

```ts
for (let attempt = 0; attempt < 2; attempt++) {
  const res = await this.control(["rm", vm]);        // 120 s class
  if (res.exitCode !== 0) { lastRm = …; break; }
  const remaining = await this.list(vm);             // control ls, 120 s class
  if (remaining.length === 0) return;
}
const remaining = await this.list(vm);               // 120 s class
```

Why real (traced): every `control` call defaults to `DEFAULT_EXEC_TIMEOUT_MS`
= 120 000 (transport.ts:41; driver.ts:690). The minimum path — box already
gone, the GREEN-round case — is rm + confirming list = 240 s of declared
ceiling against 120 priced. The code-worst path (rm exits 0 while the box
stays listed, the MEASURED 25 s+ destroy lag that motivated this whole
finally) is 2 rm + 3 list = 600 s, plus the same unpriced delta inside
`fleetLeftovers`'s "destroy pass" (another destroyQuietly at code-worst). The
audit's own stated method — "priced at DECLARED CEILINGS and not at typical
latency", reinforced by round 4/B20's finding that pricing the
box-absence poll at 4 attempts while the code said 6 was a defect — makes
this the same drift class, in the `finally` rather than the body. With this
and finding 2 corrected, the fully-degraded sum exceeds the 8 000 s runner
ceiling, i.e. the one abort path the ceiling exists to make unreachable
(bun test-timeout firing before the `finally` completes → box left billing,
minted key left live) is reachable again in the degraded regime the audit
claims to bound. It cannot affect a healthy round.

Minimal fix: price the destroy legs at code — `destroyQuietly`: rm + list
minimum (240), 2 rm + 3 list worst (600); give `fleetLeftovers`'s "destroy
pass" the same number — then re-derive the ceiling (with finding 2's lines the
corrected sum is ≈ 8 475–8 875 s; raise to ~9 000 s and update the header's
BOX-TIME line, per the audit's own closing instruction).
