## Findings

- **AC7's negative control is unrealized: nothing fails if `writeEvidence` stops stamping** — violates AC7 ("a writer that omits the field … MUST fail this one") and DOD Integration. **HIGH.** Evidence: the `swarmclawForkRev` stamp exists (`tests/fleet/e2e/sc2-harness.ts:366`) but no test in the diff or the repo asserts it — `writeEvidence` is imported only by the two live sc2 tier tests (`sc2-6-lease-kill.live.test.ts`, `sc2-7-protocol-branch.live.test.ts`), and `tests/fleet/swarmclaw-fork-pin.test.ts`'s real-corpus test is admitted vacuous in its own comment ("no evidence file carries a swarmclawForkRev stamp yet"). If a harness refactor drops the stamp, every future round is unstamped → `findStampedRevs` returns `[]` → files are skipped, never "unmapped" → the alarm stays permanently green with zero signal, exactly the silent-green failure the AC names, and Z3's evidence lands unalarmable. One small fixture test (call `writeEvidence` against a temp dir or assert the stamped copy) closes it.
- **AC4's equality target is asserted by no test: pin == newest round's manifest-row rev** — violates AC4 ("equals the rev the manifest's provenance row records for the newest round") and DD-28.26(9) ("AC4's equality target = the newest round's recorded/bracketed rev"). **MED.** Evidence: the only coherence test asserts `meta.pinRev === PIN` and `meta.pinnedAt === SWARMCLAW_FORK_REV_PINNED_AT` (`tests/fleet/swarmclaw-fork-pin.test.ts:1114-1123`); nothing ties `meta.pinRev` — or the pin — to the newest `rounds[]` row (today `2026-09-30T15-20-38-997Z-…json` → `cb2e1ca3…`, which does equal the pin), and the alarm never checks a post-pin row's `rev` against the pin. A bump PR that appends rows with the new rev but forgets the pin (or vice versa: pin bumped, manifest stale) passes every test in CI; the drift is discovered by a human reading the file.
- **AC2's "closed" state vocabulary is not closed on the real wire, and the gap is unrecorded** — violates AC2 (pin the vocabulary "exactly as enumerated by the module's own docblock") as a contract-text-vs-surface contradiction. **MED.** Evidence: `src/fleet/status.ts:136` closes the `StatusRow["state"]` union with a deliberate open member `| (string & {})`, and `approvalRowFields` (`src/fleet/status.ts:822-833, 913-917`) renders unknown approval states — any sanitized record-supplied word, or `"(unknown approval state)"` (`:348`) — onto the wire as `state`, fail-visible by design. The pin (`STATUS_VOCABULARY).toContain(rowOut.state)`, `observe-contract.ts`) passes only because its probed records carry no approval extension; one future fixture with an unrecognized approval state turns the contract suite red on legitimate, spec-sanctioned output, and a fork coding against the pinned 16-word set hits a row its contract says cannot exist. DD-28.5 carefully records the schema-version debt; this second debt is recorded nowhere (not in DD-29, not in the helper's docblock).
- **AC3's "no box probe, no run lock" is asserted only in prose, not by the pin** — violates AC3 ("asserts from the registry facts that `result` takes no `--driver`, no box probe, and no run lock (poller-safe by construction)"). **MED.** Evidence: `observe-contract.ts` asserts the registry half (`row.flags` lacks `--driver`, exit row `[0,2,4,6]`) but the box-free/lock-free half lives only in the docblock ("buildResult is a pure record read … asserted from registry facts" — the registry carries no such fact). The result probes run with a working `FakeDriver` and `goodLedger` in deps, so if `buildResult` ever grew a driver touch or a lock acquisition the suite stays green. The purity is real today (`src/fleet/result.ts:83-139` — `store.get` + `existsSync` only), but the AC's negative-control discipline is about what *fails*; a throwing-driver/throwing-ledgerFactory probe (expect exit 0 anyway) is the missing assertion.
- **`expectExactFields` now exists twice, and the refusal mechanism itself is tested nowhere** — against Files-to-Modify's rationale for `tests/fleet/observe-contract.ts` ("so the surface is asserted once") and weakens AC1/DOD-Contract ("missing AND extra-field refusals demonstrated"). **LOW.** Evidence: near-identical copies at `tests/fleet/q1-contract.test.ts:84-95` and `observe-contract.ts` (differing only in the hint prefix). Neither the original suite nor the extension has ever fed a fat/short payload through the helper and asserted the failure — a future edit that breaks either copy's `missing`/`unexpected` computation fails nothing until a real drift happens to interact with the bug. Exporting one helper (or one meta-test) closes both halves.
- **`validateEvidenceForkRevs` silently skips unparseable evidence JSONs** — AC6-adjacent ("every `swarmclawForkRev` field in an evidence JSON is validated"; the alarm's whole point is never silently green). **LOW.** Evidence: `scripts/swarmclaw-fork-pin.ts` `walkJsons` catches `JSON.parse` failure and pushes `{ file, parsed: undefined }`; `findStampedRevs(undefined)` returns `[]`; the file is neither validated nor reported as unmapped/malformed. A truncated or hand-corrupted evidence JSON is invisible to the alarm — narrower than the AC7 writer gap but the same silent-green class; a `failures.push(\`unparseable evidence file ${rel}\`)` in the catch closes it.
- **The sc2-1-5 manifest row's citing timestamp is a midnight placeholder** — AC5 precision ("citing: merge-sha(s) + round timestamp"). **LOW.** Evidence: `"file": "2026-09-28-sc2-1-5-code.json"` carries `"timestamp": "2026-09-28T00:00:00Z"` — a day-start bracket for a rolling corpus file whose real last-write instant is unknowable from the row, while every other row uses the leg's actual timestamp. Legitimate under DD-28.26(9) ("timeline-bracketed inferences") and harmless while pre-pin, but it is the row shape future directories (Z3's `v6-z3/`) will copy; a bracket at the round's end (`23:59:59Z`) would mis-bracket less.
