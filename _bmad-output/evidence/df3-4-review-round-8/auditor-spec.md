# Acceptance audit — PR #150 vs df3-4-approval-gate-attach-steering.md

Scope: spec (`_bmad-output/sprint-artifacts/dark-factory-v5/stories/df3-4-approval-gate-attach-steering.md`, 703 lines) against chunks 1–4 (main source only). Test chunks 5–10 and the DoD test checklist were not audited.

## Findings

**HIGH** — AC6 round trip cannot close on the shipped real substrate — AC6 / Trigger Surface "transport is real" — `src/fleet/attach.ts:17-31,1334` + `scripts/pipeline-run.ts:1722` — The two transport legs address different filesystems. The host leg appends via `driver.exec(vm, ["sh","-c",APPEND_SCRIPT], …)` into the **box's** `/run/steering/inbox.ndjson` (chunk-2 attach.ts:1120-1128, append call at :1334); the engine leg, wired host-side in `pipeline-run.ts` (`inbox: localSteeringInbox()`), drains the **host's** `/run/steering/inbox.ndjson` with plain `fs` (attach.ts:496-521). exe.dev boxes are remote VMs; nothing mounts one onto the other, so on a real run no message ever flows, no ack is ever produced, and `attach-acked` is unreachable. The live tier-1 test pins the broken shape as the shipped contract (`tests/fleet/e2e/tier1-attach-transport.live.test.ts:24-31`: "production has NO in-box engine today… a real box acks NOTHING, and `attach-not-acked` / reason `no-ack` / exit 6 … is the SHIPPED CONTRACT"). AC6's letter narrows to "a live box under the `fake` driver", so the fake-topology evidence is spec-conformant — but the operator-facing remediation printed on real runs ("the message IS queued in the box — check the resident agent is running", scripts/fleet.ts attach `no-ack` arm) is false: nothing will ever drain the box-side file. The Dev Agent Record's sprint-level note claims "DF3.4 is unaffected in practice"; that claim is wrong for the round trip, and no numbered deviation records the two-filesystem split (Deviation 4 covers only copyFile→exec).

**MEDIUM** — Approval namespace registered at `schemaVersion: 2`, spec pins 1 — AC1(a) / Infra Prerequisites / DoD Contract (`schemaVersion: 1`) — `src/providers/run-record.ts:300` — `EXTENSION_NAMESPACES.approval.schemaVersion` is 2, with a `retired: { supersededReportId: "supersededReportIds" }` migration (run-record.ts:300-316). The change is argued in-code (two sources of truth in an audit trail) and was applied by review round 6 ("`schemaVersion` → 2"), but it contradicts the story's stated contract line and is absent from the Dev Agent Record's nine-item deviation table.

**MEDIUM** — "Configurable per run" policy timeout is unimplemented — Technical Notes :258-259 ("default policy timeout 24h, configurable per run, floor 60s") — `src/fleet/approval-gate.ts:590,1165-1173` — `timeoutMs` lives on `GateDeps`, i.e. per construction, and no per-run surface exists: `recordApprovalPort` is built with `{ bundleDir }` only (`src/reverify/runner.ts:1652`), the CLI calls `sweepExpired({ store }, …)` / `submitDecision({ store }, …)` with no `timeoutMs` (`scripts/fleet.ts:2772,2768`), and no flag, record field, or env carries a per-run policy. The shipped timeout is a flat 24h; the floor/ceiling clamp is implemented, the configurability is not.

**MEDIUM** — Stranded `pausing` run sends the operator in a remediation circle — AC5 / AC7 / Deviation 11 — `src/fleet/status.ts:509-535` + `scripts/fleet.ts` not-decidable arm — `fleet status` relabels `pausing` → `awaiting-approval` with no countdown (approvalRowFields `effective === "pausing"` arm, status.ts:517-535), while `fleet approve` on that run exits 5 with "re-run once `fleet status` reports awaiting-approval" and `fleet attach`'s refusal says "decide it with `fleet approve`/`fleet reject` instead". Status already reports that state and will report it forever; approve still refuses; neither remediation names the actual exit (re-running reverify, which re-presents the bound reportId). The two surfaces contradict each other exactly where an operator is stranded.

**MEDIUM** — A paused run whose box is still listed is never shown as paused — AC7 ("each paused run appears with its state") — `src/fleet/status.ts` rowForRecord override, guarded by `if (box === undefined)` — The approval override fires only when the driver's box list lacks the box. A run stranded in `pausing` by the no-teardown-seam refusal or a failed teardown still owns a live, billing box, and `fleet status` reports it `live` — hiding precisely the state INV-APPROVE-6's guard creates and AC1(c)'s resume exists to clear. The code's stated reason (a live box "outranks the pause") is a judgement call the AC's letter does not license.

**MEDIUM** — Unrecorded scope expansion into stories this one does not own — Files to Modify list / Dev Agent Record discipline — `src/providers/exedev/driver.ts:58-93,250-266`, `src/providers/bounded-exec.ts:19-38`, `scripts/lib/cost-ledger-opts.ts:205-280` — Box create now **hard-fails** on substrates without passwordless sudo (`steering-channel-unprovisionable`, a DF2.1-owned create contract), `EXEC_MAX_OUTPUT_BYTES` doubles 512 KiB → 1 MiB (a shared heap bound for every exec consumer, whose old header said "the cap is about heap, not about display"), and the ledger migration temp handling changes.
