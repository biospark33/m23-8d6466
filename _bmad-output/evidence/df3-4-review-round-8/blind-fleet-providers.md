# Blind Hunter — chunk-3-fleet-providers

- **MEDIUM** `pausing` renders as `awaiting-approval` with no distinguishing field — `src/fleet/status.ts:545` — trigger: teardown crashes between destroy and promotion, leaving a `pausing` record on disk indefinitely (the chunk itself calls this "reachable and persistent"). `approvalRowFields` maps it to `awaiting-approval` ("this run is waiting on you") with no `expiresInMs`, and the only hint is an absent countdown; the operator runs `fleet approve`, which `submitDecision` refuses as `not-decidable` for `pausing`. The old divergence (status said `timed-out`, gate said `not-decidable`) was fixed by making status say the state the gate will still refuse.
- **MEDIUM** shed note echoes raw, unvalidated values to stderr before the secret scan runs — `src/providers/run-record.ts:798` — trigger: a write of a >256-element `strings` value whose dropped head contains a credential: `shedStrings` prints `value.slice(0, dropped).join(", ")` verbatim, then `assertNoSecret` runs on the SHED value, so an element that was dropped passes the scan and the write succeeds — the credential is on the log and never on disk, but INV-2 leaked at the note. Same class in the migration head-shed note at `src/providers/run-record.ts:975`, whose `history.slice(0, shed)` comes from the read path where `assertNoSecret` is skipped entirely. One-line fix: print only lengths/ids after redaction, or shed after the scan.
