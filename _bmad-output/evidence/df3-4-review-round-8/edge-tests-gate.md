**HIGH** — `withTeardownClaim`'s reclaim/wait loop is never exercised — `tests/fleet/approval-gate.test.ts:432-479` — the only `.teardown.claim` mentions in the whole suite are an in-process serialization count and a leftover-file assertion; the dead-pid reclaim (`rmSync` + retry), the unparseable-pid reclaim, and the ENOENT-then-retry arms of `src/fleet/approval-gate.ts:1116-1140` have zero coverage, so a regression there (e.g. swapping the reclaim `continue` for a spin) passes everything. **HIGH** — `awaitDecision` with a non-finite `waitMs` hangs forever and nothing pins it — `tests/fleet/approval-gate.test.ts:865-889` — `pollMs` is clamped for non-finite input and tested, but `waitMs` is not guarded or tested (`src/fleet/approval-gate.ts:1349` + `:1358`: `Date.now() + NaN` → `Date.now() >= NaN` is false → the loop never returns). Fix: add a waitMs NaN/Infinity case asserting the same clamp-or-floor posture as pollMs (or pin the hang as a known bug).
