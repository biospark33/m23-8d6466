1. **fixed** — `withTeardownClaim` no deadline: added `CLAIM_TIMEOUT_MS = 300_000` (approval-gate.ts:126, teardown-scale ceiling mirroring `LOSER_TEARDOWN_TIMEOUT_MS` in fanout-primitive.ts, not the 5 s lock scale a real teardown blows through) + deadline check at :1226-1232 throwing a typed error naming the claim path, the holder pid, and the operator remedy (check for sandbox-teardown, remove the claim only if none is running, re-run the resume).
2. **fixed** — empty/unwritten claim treated as dead: age precondition added at :1206-1214 — `age > LOCK_STALE_MS` is checked BEFORE the content read, so the `wx`-to-write window's pid-less file is never reclaimed; past that age, unreadable pid reclaims (safe here — the failure direction is a concurrent teardown, the pre-claim status quo, documented in the header).
3. **fixed** — `submitDecision` bundle check: `assertBundlePresent(deps, runId, "decide")` at :1333, on the `awaiting-approval` path after expiry/terminal/not-decidable short-circuits, matching the pause/rebind/resume verb-tag style.
4. **fixed** — skipped promotion returned `requested`: the promote step now returns a boolean; a lost race returns `{outcome:"pause-in-progress"}` (:1124-1143), reusing the existing `ApprovalOutcome` member — no shape change for callers (runner.ts already flags that outcome and re-presents the bound reportId, which re-runs the pause). `ctx.outcome`/`ctx.state` stay truthful on the event line. **Two test expectations changed** (intentional behavior change): tests/fleet/approval-gate.test.ts:467 concurrent-resume test now accepts `pause-in-progress` alongside requested/rebound, with a comment; the pre-existing `toEqual({outcome:"requested"})` assertions all still pass because the race loser path is rare in-test.
5. **fixed** — `awaitDecision` NaN/Infinity `waitMs`: non-finite now falls back to `DEFAULT_TIMEOUT_MS`, negative clamps to 0 (:1461-1466), same posture as the `pollMs` clamp above it.
6. **fixed** — throw between `wx` create and content write strands an unrecoverable empty lock: content write moved inside the fd's try with a removal-on-failure fenced on our own inode (:196-215); if even the removal fails, the next waiter's stale-age/no-pid door recovers it.
7. **fixed** — dead `requestId` re-stamp: `...(rec.requestId === undefined ? {} : { requestId: rec.requestId })` removed from the fresh-pause write (now :1023). It was a no-op re-stamp of a field `store.create` leaves undefined and only dispatch writes (the only external reader, scripts/fleet.ts:2732, reads `rec.requestId` first, extension as fallback — removing the re-stamp cannot change any value, since deep-merge already retained whatever was there).
8. **fixed** — ENOENT `continue` skipping the sleep: the vanish arm now falls through to the deadline check and `LOCK_POLL_MS` sleep (:1222-1224), same reasoning as the approval lock's own loop.
9. **fixed** — `HEAD_SHA_RE` rejects uppercase hex: `headSha` is lower-cased before validation (:918-920); stored form is the normalized lower-case, so every downstream comparison reads the one form. **Test expectation changed** (intentional): the "uppercase headSha is a schema rejection" case was replaced with "an uppercase headSha is the SAME commit — normalized and bound" (tests/fleet/approval-gate.test.ts:186-197) asserting the stored value is lower-case; a `non-hex` case was added to keep 40-char rejection coverage.
10. **fixed** (comment-only) — `linkSync` restore double-link: verified the code is already correct — `rmSync(claimPath)` after a successful link cannot throw out of this block (the `claimed` rethrow only fires on errors thrown from the try, and a failing janitorial unlink after a successful restore would abandon a RESTORED lock, the wrong direction). Added a comment naming this asymmetry deliberately (:311-316) rather than changing code.
11. **fixed** (comment-only) — "no instant of vacancy" contradicted the EEXIST arm: comment corrected (:302-308) to state exactly what is true — the rename-away DID vacate the path and EEXIST is the proof a successor won it; the link's guarantee is that the restore adds no second vacancy and clobbers nothing on loss.
12. **fixed** — `historyOf` coerced non-strings into `[object Object]`: type-guard `filter((id): id is string => typeof id === "string")` (:740); the store's `strings` kind rejects non-strings on write, so a non-string here is a hand-edited record and skipping it keeps the audit trail provably wrong rather than plausibly wrong.
