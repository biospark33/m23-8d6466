**Date:** 2026-09-19 · **Focus:** what four prior rounds still missed — the cgroup mechanism under
concurrency, restart and partial failure; whether any Dev Agent Record claim is false; and whether

6 findings. No CRITICAL or HIGH in the mechanism itself. All resolved in-round.

| # | Sev | Finding | Resolution |
|---|-----|---------|------------|
| 1 | MED-HIGH | **The committed branch was red** (`PLACEHOLDER_WALK_DIGEST`) while the Dev Agent Record said "everything host-side is green". Three rounds had knowingly signed off on it. | Record rewritten to state the exact suite scope and the known-unrelated failures; the digest is re-derived and amended in last, per the pin file's own "re-pin LAST" discipline. |
| 2 | MED | **`createLeaf`'s pre-clean could kill a live leaf, and its safety comment said it could not.** Round 1's fix made `removeLeaf` write `cgroup.kill` FIRST, so the pre-clean no longer fails EBUSY on an occupied leaf — it empties it by SIGKILL and removes it. | 3 | MED-LOW | **The OOM arm fired on any rejection whose leaf reported `oomKilled`, not only on a kill.** `oom` counts own-limit events, and where an allocation can fail gracefully the kernel returns `-ENOMEM` and the task survives — so pi could take that, finish, exit 0, and the call still reject on a reply-artifact persist failure or a provider 429, landing a `watchdog_kill` row with `status:"stopped"`/`exitStatus:"overflow"` for a host-side fault. Those rows are D4's tier-2 demotion evidence — the same failure class rounds 1 and 3 each closed once from a different door. | Fleet now ANDs the kernel's counters with an actual signal death: the counters say the limit fired, a new `killedBySignal` flag says the process died of it. A new negative control stages `oom 1` on a cleanly-exiting child and asserts `oomKilled` stays false; the two kill tests now drive a real SIGKILL through a new fixture knob. |
| 4 | LOW-MED | **Nothing pinned that a BOUNDED call spawns through the wrapper.** An implementation that deletes the wrapper and writes `proc.pid` from the parent after `Bun.spawn` passed every assertion in the file — the one-pid read-back, the numeric contract, the exit-97 arm (which keys on the exit code plus `leafDir`), `runWrapper` (which exercises the script standalone) and the INV-MEM-3 test (which reads pi's own argv, identical either way) — while re-opening the exact unbounded window the wrapper exists to close. | Added the `_lastSpawnArgvForTest()` seam and two tests: a bounded call must spawn `sh -c <PLACEMENT_SCRIPT> _ <leaf> <pi argv…>`, and an unbounded one must spawn pi directly with no wrapper. |
| 5 | LOW | **`stop()` could outrun the in-flight call's leaf teardown.** It resolves as soon as `proc.exited` does, while the interrupted call still has both output streams to drain before its `finally` reaches the teardown — so a caller ending the process on `await stop()` leaves a leaf with `cgroup.kill` never written. Not reachable from the shipped runner; latent. | `stop()` now finishes the teardown itself on the hoisted `currentLeaf`; whichever path arrives second finds the leaf gone and swallows the ENOENT. |
| 6 | LOW | **Two changed files were missing from the Files budget and the Shipped table:** `tests/fleet/fixtures/fake-pi-resident.ts` (a SHARED fixture) and `tests/scripts/build-exedev-image.test.ts`. | Both added, with the fixture's additive/env-gated nature and the pin re-derivation's role stated. |
