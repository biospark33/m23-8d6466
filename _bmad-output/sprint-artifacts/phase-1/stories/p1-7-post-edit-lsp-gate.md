# P1.7: Post-edit `lsp_diagnostics` gate blocks emit on dirty changed files

**Story Points:** 3 *(SP estimate note: 3SP covers gate + waiver + streaming. If LSP server integration requires custom adapter work beyond `pi-lens lsp-diagnostics`, reconsider as 5SP at sprint planning.)*

## Spec Reference

- PRD §6.4 (Execution — Pi team / pi-lens); FR-EX-11, FR-EX-12; NFR-SAF-4, NFR-SAF-6, NFR-PERF-6
- PRD §4.5 ("the single strongest lever — the post-edit diagnostics gate"); §4.6 (launcher stdout protocol, mandatory `changed_files`)
- Phase exit gate: PRD §13 Phase-1 item 5 ("the node **blocks emit while `lsp_diagnostics` shows errors on changed files**; post-edit gate, waivers logged")

## User Story

As a **Dev manager** driving the `qds-piv-loop` implement node,
I want **the team lead to run `lsp_diagnostics` over the union of all changed files and refuse to emit node output while any error remains (or log an explicit waiver when the LSP surface is unavailable)**,
so that **"compiles + typechecks" becomes a hard precondition of every handoff (drives loop L1, fewer in-run defects — goal G2 quality yield).**

## Overview

This slice cuts through the Pi-team launcher (`scripts/pi-team-launch.sh`) lead-emit path: the lead reads each worker's `changed_files: string[]` from its NDJSON SSE stream reply (the per-worker NDJSON SSE stream established by P1.6's `WarrenClient` SSE subscription); the lead computes the set-union (deduplicated: duplicate paths across workers produce a single entry), invokes pi-lens `lsp_diagnostics` (headless, machine-readable JSON confirmed v3.8.47, OQ-2) over that union, and **gates stdout**. Zero errors → emit the merged JSON node output. Errors present → no emit (non-zero exit / re-request). When no language server exists for a changed file, `lsp_diagnostics` is unavailable, or it breaches the NFR-PERF-6 ≤3s p95 budget, the gate degrades to pi-lens `ast_grep_*` + test-pass with a **logged waiver** (FR-EX-12). One atomic unit because the gate is meaningless without both the union-collection protocol and the fallback+waiver path wired together.

## E2E Slice

**Demonstrable behavior:** The implement node runs `scripts/pi-team-launch.sh --task … --archetype C --context-path ./ctx` against a worktree where a worker introduced a deliberate type error in a changed file. The launcher lead reads workers' `changed_files` from their NDJSON stream replies (P1.6 streaming architecture), runs `lsp_diagnostics` over the union, sees `errorCount > 0` (computed as `SUM(lsp_diagnostics[*].errorCount)` — the sum of per-file diagnostic error counts across all changed_files, NOT the length of a flat details array), and **writes nothing to stdout / exits non-zero** (gate held). On a clean re-run with 0 errors, the lead writes the single merged JSON object (`{ changed_files, result, partial:false, exit_class:"transient", waivers:[] }`) to stdout. With the LSP surface forced unavailable for a changed file's language, the lead emits **with `waivers:[{file, reason:"no_language_server", fallback:"ast_grep+tests"}]`** populated.

**Wiring closed:** On completion of this story, running `scripts/pi-team-launch.sh` on a worktree carrying a known type error on a changed file produces **no stdout node output and a non-zero exit (gate held)**, and on the clean run produces the merged JSON with `waivers:[]`, using only code merged by this story (lead NDJSON stream collection + `lsp_diagnostics` invocation + fallback/waiver emit in `scripts/pi-team-launch.sh`). No stub, no `TODO: wire later`, and no sibling story is required to make this behavior real. Predecessors, if any, are dependency edges (listed below), not unfinished wiring inside this story.

**Dependency edges (predecessors):** P0.6 (pi-lens + LSP servers on PATH, headless `lsp_diagnostics` machine-readable spike — OQ-2 RESOLVED; pi-lens diagnostic taxonomy — waiver `reason` enum values in this story are a strict subset of P0.6's pi-lens diagnostic waiver taxonomy, and the e2e test uses P0.6 waiver types directly) · P1.6 (the merged-output lead-emit path that this gate guards; defines the NDJSON SSE streaming architecture via `WarrenClient` from which the lead reads worker replies). Both are dependency edges, not leftover wiring.

## Acceptance Criteria

> ≥3 scenarios, Given/When/Then. Exactly one tagged (make-or-break) and binary.

1. **(make-or-break)** Given a worktree where a worker reported a changed file carrying a known type error, When the lead runs `lsp_diagnostics` over the union of all workers' `changed_files` at node emit, Then `errorCount > 0` (where `errorCount = SUM(lsp_diagnostics[*].errorCount)` across all changed_files — the sum of per-file diagnostic error counts, NOT the length of a flat details array) and the launcher writes **nothing to stdout and exits non-zero** (no node emits over a known type error on a changed file).
2. Given all changed files are clean (0 diagnostics errors), When the lead runs the union gate, Then the launcher writes exactly one merged JSON object to stdout with `waivers: []` and exit code 0. **Test must verify that `waivers: []` was explicitly set (not omitted):** gate output always contains the `waivers` key, even when empty. Omission ≠ empty array in the test assertion.
3. Given a changed file whose language has **no server on PATH** (or `lsp_diagnostics` exceeds the NFR-PERF-6 ≤3s p95 budget), When the gate runs, Then the lead degrades to `ast_grep_*` + test-pass for that file and emits with a populated `waivers[]` entry (`reason` from P0.6 pi-lens waiver taxonomy subset, `fallback:"ast_grep+tests"`) — never a silent skip. **Test verifies waiver reason string matches one of the P1.7 granular sub-reason values:** `"no_language_server"|"headless_unavailable"|"latency_budget_exceeded"` (each mapping to P0.6's `'fallback'` category). Unknown reason strings cause a test failure.
4. Given a worker reply that **omits** `changed_files`, When the lead aggregates the union, Then the lead **fails the node** (logic error, non-zero exit) — this is a node failure, NOT a waivable diagnostics failure (CORRECTNESS-C).

## Technical Notes

- **Contracts/Schema:** Worker NDJSON stream reply MUST carry `changed_files: string[]` (the lead reads workers' NDJSON SSE stream replies established by P1.6's `WarrenClient` SSE subscription). The lead validates `changed_files` explicitly per §4.6. Merged stdout object: `{ changed_files: string[] (set-union, deduplicated — duplicate paths across workers produce a single entry), result: object, partial: boolean, exit_class: "transient"|"overflow"|"logic", errorCount: number (derived from pi-lens `lsp_diagnostics` structured JSON output: **the sum of per-file diagnostic counts across all changed_files, NOT the length of a flat details array**; computed as `SUM(lsp_diagnostics[*].errorCount)` where each per-file `errorCount` is the count of `severity: "error"` items in that file's `details` array; 0 when all diagnostics pass), lsp_diagnostics: Array<{ file: string, errorCount: number, details: Array<{ line: number, severity: "error"|"warning", message: string }> }> (the structured gate evidence — one entry per changed file in the union; each entry's `errorCount` is the count of `severity: "error"` items in its `details` array; the top-level `errorCount` is the sum of all per-file `errorCount` values), waivers: Array<{ file: string, ruleId: string (identifies the specific gate rule waived — for P1.7 this is always `"lsp-diagnostics"`, the diagnostic gate rule; aligns with the `(file, ruleId)` DB key and stderr log format), reason: "no_language_server"|"headless_unavailable"|"latency_budget_exceeded", fallback: "ast_grep+tests" }> }`. Waiver `reason` enum values are sub-categorizations of P0.6's `'fallback'` category — P1.7 granular values `"no_language_server"`, `"headless_unavailable"`, and `"latency_budget_exceeded"` each map into P0.6's `'fallback'` reason; if P0.6 adds or renames a reason, this enum tracks it. **Waiver reason enum:** the full P0.6 taxonomy is `'fallback'|'override'|'suppressed'|'accepted-risk'`. The enum is extensible — new reasons can be added without schema changes. `'fallback'` is the only reason P1.7 auto-applies (when LSP server is unavailable). The AC-3 reasons (`"no_language_server"`, `"headless_unavailable"`, `"latency_budget_exceeded"`) map to the `'fallback'` category with specific sub-reasons for observability. Backward-compat: `waivers` defaults to `[]`; existing single-worker (Solo) nodes still produce the union of one list.
- **Schema cross-reference (P1.6 base extension):** `lsp_diagnostics` is an additive extension of P1.6's base NDJSON stream output. Base fields (`changed_files`, `exit_class`, `durationMs`) are inherited from the P1.6 lead-emit contract; `lsp_diagnostics` and `waivers` are P1.7-specific additions. Any P1.6 schema changes to base fields propagate here automatically. **Name disambiguation:** `lsp_diagnostics` in the gate output schema refers to the diagnostic data array. It is distinct from the pi-lens CLI command `lsp-diagnostics` (kebab-case tool name). No collision in implementation — one is a JSON field name (snake_case), the other is a CLI command (kebab-case).
- **Integration points (each wired & exercised in this story):** lead reads each worker's NDJSON SSE stream reply (P1.6 `WarrenClient` subscription) → set-union of `changed_files` (deduplicated, not concatenated — a path appearing in N workers appears once in the union) → pi-lens `lsp_diagnostics` (file/dir/batch, `--mode json`/`--mode rpc`, structured `details` per `tools/lsp-diagnostics.ts:451-470`) over the union → stdout gate. `errorCount` is computed as the sum of per-file diagnostic counts across the union (`SUM(lsp_diagnostics[*].errorCount)`, where each per-file `errorCount` is the count of `severity: "error"` items in that file's `details` array; sum = 0 means clean). Fallback path → pi-lens `ast_grep_*` + the worktree's test command. Waiver records are counted by NFR-SAF-4 / capped by NFR-SAF-6.
- **Files / functions touched:** `scripts/pi-team-launch.sh` (lead-emit block: NDJSON stream collection, set-union compute, diagnostics invocation, gate, fallback, waiver record); the worker reply validator; the merged-output schema definition consumed by the launcher.
- **Gate is binary, no partial pass:** the gate is a strict boolean — ANY file in the union with `errorCount > 0` blocks emit. There is no "partial success" where some files pass and others fail. If any file has a non-zero error count (from `lsp_diagnostics` structured `details` array), the gate holds and no stdout is written. The only emit paths are: (a) all files clean (`errorCount === 0` across the entire union), or (b) some files waived via explicit `waivers[]` entry AND the remaining non-waived files are all clean.
- **Gate interception point in the stream:** the gate intercepts at the lead-emit decision point — specifically, after all worker NDJSON SSE stream replies are collected and the set-union of `changed_files` is computed, and BEFORE stdout write. The gate is a synchronous check between union-computation and emit: union → `lsp_diagnostics` invocation → gate decision → emit-or-hold. There is no async overlap; the gate is a blocking decision.
- **LSP diagnostic item format:** follows pi-lens `lsp_diagnostics` structured output: `DiagItem { file: string, line: number, severity: "error"|"warning"|"info"|"hint", message: string }`. Only `severity: "error"` items count toward `errorCount` and block emit. `severity: "warning"` items are included in the `details` array for observability but do NOT increment `errorCount` and do NOT block emit. `severity: "info"` and `severity: "hint"` diagnostics are logged for observability only — they do not appear in the gate's `errorCount` and do not block emit. This matches the `details` array structure from `tools/lsp-diagnostics.ts:451-470`.
- **exit_class cross-cut consistency:** the `exit_class` field in the merged-output object uses the verified-correct mandatory enum (R2 CC-2): `"transient"` (normal completion), `"overflow"` (context exceeded), `"logic"` (correctness failure). No other values are permitted. This enum is shared across all stories and MUST NOT diverge.
- **Guards/limits:** `lsp_diagnostics` invocation bounded by NFR-PERF-6 (≤3s p95) — a breach is a waiver trigger, never an unbounded hang. Waiver-rate ceiling ≤5% of emitted nodes (NFR-SAF-6) — out of scope to enforce per-run here, but each waiver is logged as a first-class record for that aggregate. First-invocation LSP cold-start latency (server process spawn) is mitigated by the NFR-PERF-6 ≤3s budget — if cold-start exceeds the budget, the gate degrades to the waiver path (AC-3) rather than blocking indefinitely. A warm-server mode (LSP process kept alive across invocations) is a future optimization, not a Phase-1 requirement.
- **Citation caveat:** File:line references in this story (e.g., `tools/lsp-diagnostics.ts:451-470`) are best-current-knowledge at spec time and may shift during P0.6/P1.6 development. The derivation logic (which pi-lens output supplies which field) is the contract, not the exact line numbers.
- **Waiver idempotency:** Waiver records are keyed by `(file, ruleId)`. Re-running the gate on the same `changed_files` produces identical waiver records. Upsert semantics: if `(file, ruleId)` already exists, the waiver is skipped (not duplicated). This ensures retry-safety — a gate retry does not double-count waivers toward the NFR-SAF-6 ceiling.
- **`partial` field semantics:** `partial` in the gate context is always `false` for P1.7 (binary pass/fail gate). It exists in the schema for forward-compatibility with future partial-gate modes. Consumers should not rely on `partial: true` in P1.7's output.
- **changed_files union cap:** The `changed_files` union is capped at 10,000 entries. If the union exceeds this, the gate logs a stderr warning and processes only the first 10,000. This prevents pathological workers from producing unbounded sets.

## Security Invariants

> Triggered: input/file (deserialization/parse of worker replies; file paths fed to `lsp_diagnostics`).

- **INV-1 (parse-validate, never trust):** worker NDJSON stream replies are `JSON.parse`-only (parse-only schema, §5.2) — the lead MUST schema-validate `changed_files` is a `string[]` before use; a malformed/missing `changed_files` **fails the node** (AC-4), it is never coerced to an empty union (which would silently pass the gate).
- **INV-2 (no path escape):** every entry in the union `changed_files` is resolved and constrained to the run's worktree path (`--worktree`/inherited `cwd`); a path resolving outside the worktree is rejected (the gate never runs `lsp_diagnostics` over arbitrary host files). **Symlink escape:** `realpath()` resolves symlinks to their targets. If a changed_file symlink target resolves outside the worktree root (after `realpath` canonicalization of both the symlink target and the worktree root), the file is excluded from diagnostics with a stderr warning. This prevents symlink-based worktree escapes even when `realpath` is used for path traversal prevention. **Prefix-match enforcement:** after `realpath` canonicalization, verify the resolved path is within the worktree using platform-agnostic comparison: `!path.relative(worktreeRoot, resolvedPath).startsWith('..')`. This handles both `/` (POSIX) and `\` (Windows) path separators without hardcoding a delimiter. If the resolved path is outside the worktree, exclude the file with a stderr warning. This applies to both direct path traversal (`..`) and symlink escapes.
- **INV-3 (no silent bypass):** the gate degrades ONLY via a recorded `waivers[]` entry with an enumerated `reason` (subset of P0.6 pi-lens waiver taxonomy — `"no_language_server"`, `"headless_unavailable"`, `"latency_budget_exceeded"`); there is no code path that emits node output over a non-empty diagnostics error set without either 0 errors or a logged waiver (NFR-SAF-4: 0 un-waived dirty-diagnostics emits).
- **INV-4 (no leak):** raw `lsp_diagnostics` / `ast_grep` tool output (which may echo source lines) goes to **stderr** (Warren warning channel, the finalize node stderr), never to the structured stdout node output beyond the bounded `waivers[]` summary.

## Definition of Done

- [ ] **Impl:** lead reads each worker's NDJSON SSE stream reply (P1.6 `WarrenClient`), collects `changed_files`, and computes the set-union (deduplicated — duplicate paths across workers produce a single entry) before any emit decision.
- [ ] **Impl:** lead invokes pi-lens `lsp_diagnostics` (`--mode json`/`rpc`) over the union and computes `errorCount` as the sum of per-file diagnostic error counts (`SUM(lsp_diagnostics[*].errorCount)`, NOT the `details` array length).
- [ ] **Impl:** FR-EX-12 fallback path runs pi-lens `ast_grep_*` + the worktree test command when LSP is unavailable / over budget, and writes a `waivers[]` record with `reason` drawn from P0.6 pi-lens waiver taxonomy subset.
- [ ] **Contract:** merged-output schema (incl. `changed_files` set-union, `errorCount` = sum of per-file diagnostic error counts from `lsp_diagnostics` (NOT the `details` array length), `waivers[]` with enumerated `ruleId`/`reason`/`fallback` where `ruleId` identifies the gate rule waived and `reason` values are sub-categorizations of P0.6's `'fallback'` category) defined and validated by the launcher before stdout; `waivers` defaults `[]`.
- [ ] **Security:** INV-1 enforced — a missing/malformed `changed_files` fails the node (logic error), proven by a unit test (AC-4).
- [ ] **Security:** INV-3 enforced — no emit path bypasses the gate without 0 errors or a logged waiver.
- [ ] **Observability:** every waiver is logged to stderr as a first-class record (`{file, ruleId, reason, fallback, waivedAt}`) counted by NFR-SAF-4 / NFR-SAF-6.
- [ ] **Test (unit/integration):** covers (a) dirty-union → no emit / non-zero exit, (b) clean-union → emit with `waivers:[]`, (c) missing-server → fallback + waiver, (d) omitted `changed_files` → node failure.
- [ ] **Test (unit): all-changed-files-waived path** — when every changed file has no LSP server on PATH and the fallback (ast_grep + tests) passes for all of them, emit proceeds with populated `waivers[]` (one entry per waived file) and exit code 0. Proves the waiver-only path emits successfully.
- [ ] **Test (e2e demo — MANDATORY):** run `scripts/pi-team-launch.sh` on a worktree seeded with a known type error on a changed file; assert **no stdout node output + non-zero exit** (where `errorCount` = sum of per-file diagnostic error counts in `lsp_diagnostics.details` is > 0); then fix the error and assert a single merged JSON object with `waivers:[]` is written (proves wiring closed: no node emits over a known type error; fallback+waiver path demonstrable). Uses P0.6 waiver taxonomy types in e2e assertions.
- [ ] **Test (perf):** gate invocation (set-union compute + `lsp_diagnostics` call + emit decision) completes in ≤3s for ≤50 changed files (NFR-PERF-6 budget is ≤3s p95 for the diagnostics call itself; gate adds union overhead — total gate wall-clock must stay within this budget).
- [ ] **Test (unit — zero-files edge case):** when zero changed files are reported across all workers (empty union), the gate emits the merged JSON with `changed_files: []`, `errorCount: 0`, `lsp_diagnostics: []`, `waivers: []` and exit code 0 — proving the gate handles the degenerate empty-union case without error.
- [ ] **Test (unit — mixed clean-and-dirty union):** when a subset of changed files have dirty diagnostics (at least one file with `errorCount > 0`) and the remaining files are clean, and no waivers are applied, the gate fails: no stdout output, non-zero exit, `errorCount > 0`, and the `lsp_diagnostics` array includes per-file breakdowns for BOTH clean and dirty files (dirty files with their error details, clean files with `errorCount: 0` and empty `details: []`). Proves the gate does not silently drop per-file evidence for files that passed.
- [ ] **Test (unit — malformed lsp_diagnostics):** gate receives unparseable JSON from pi-lens stdout. Gate treats the file as having 0 diagnostics (not dirty) and logs a stderr warning: `'malformed lsp output for {file}, skipping'`. Gate does NOT crash.
- [ ] **Test (unit — errorCount derivation):** gate output has `errorCount = SUM` of all per-file diagnostic counts. Verify `errorCount` ≠ length of flat details array when files have differing diagnostic counts. Specifically: given 3 files with `errorCount` values 2, 0, and 3, top-level `errorCount` must be 5, not 3 (number of files) and not the total count of detail entries across all severity levels.
- [ ] **Test (unit — mode flag):** gate invocation with `--mode json` produces stdout-only JSON output. `--mode rpc` (default) writes to the merged-output schema and optionally emits NDJSON. Verify both modes produce valid output and neither mode leaks raw LSP stderr to stdout.
- [ ] **Test (unit — truncated NDJSON):** simulate a worker that writes only partial `changed_files` before disconnecting. Gate processes available entries and logs stderr warning for incomplete worker. `errorCount` reflects only the files received.
- [ ] **Test (unit — changed_files dedup):** two workers both report `src/foo.ts` in `changed_files`. Gate output has exactly one entry for `src/foo.ts` with merged diagnostics from both workers.
- [ ] **Test (unit — stderr waiver format):** each waiver logged to stderr is a single JSON line parseable as `{file, ruleId, reason, waivedAt}`. Verify no multi-line JSON or non-JSON content in waiver stderr output.
