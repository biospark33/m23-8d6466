## User Story

As the operator, I want the factory VPS stack authored as an extension of the one deploy template, with the fleet wrapper as the only holder of the driver grammar, so that VPS day is a fire-and-verify exercise and the swarmclaw fork never learns QDS's driver grammar.

## Overview

This story authors `deploy/vps/`: a compose profile (dedicated Hindsight 0.10.0 pinned to the fork's digest; the M2 gateway slot), a Caddy host block in the template's allowlist idiom, env templates, and the deployed wrapper that `$SWARMCLAW_FACTORY_FLEET_CLI` points at. [authored] = all artifacts plus machine-checked profile/wrapper tests green with no VPS. [fired] = the operator runs the same artifacts on the box after G1–G7 GO and records smoke evidence.

**What this does NOT deliver:** no gateway authz (M2.1); no bank provisioning or round-trip verify (M1.1); no cron of any kind (A6 owns the refresh cron entry; the backup timer is the runbook's G8, zeropoint's `backup.sh`); no box-image re-pin (ops ritual — this story moves zero box-COPY-set bytes); no installer/automation — compose + operator by hand, per the template's own rule ("installed from this file by an OPERATOR … never by automation").

## Acceptance Criteria

1. **[authored] (make-or-break — the compose profile)** Given `deploy/vps/docker-compose.factory.yml`, When parsed, Then it defines exactly two services: `hindsight-qds` — image = the fork's full index-digest pin verbatim, with **exactly one host publish: the loopback map `127.0.0.1:18890:8888`** (the dedicated instance's host-side port is **18890** — never 18889, which on a both-stacks box is the platform tenant stack's map and the wrong-instance shape M1.1's AC1 forbids; compose-network addressing stays primary) — and `m2-gateway` — image `ghcr.io/${QDS_FACTORY_OWNER}/qds-m2-gateway:${M2_GATEWAY_TAG}`, seeded-once tag, loopback-only healthcheck. *Negative control: **a compose exposing 18889 publicly** — any `ports:` entry with a non-loopback host IP, any host-port mapping other than the single `127.0.0.1:18890:8888` (in particular anything on host ports 8888 or 18889 at all), or any Caddy row whose upstream is a hindsight service — MUST fail this one (the profile test refuses it by name).*

- **Region ownership on shared files:** nothing under `src/`, `oci/`, `scripts/`, or `cli-anything/` is touched — the box COPY set is byte-identical, so **no re-pin ritual is owed**. `src/fleet/verbs.ts` is read-only here (listed in Files to Modify to state the registry is consumed, not edited).
- **Hindsight pin advance:** the digest literal advances only by a deliberate bump PR re-copied from the fork's pin file, verified at evidence rounds — the `SWARMCLAW_FORK_REV`/`FORK_IMAGE_TAG` seeded-once discipline, not a new pin machine.
- **Ordering against M1.1/M2.1/A6:** M1.1's round-trip legs consume `hindsight-qds`; M2.1's integration acceptance consumes the gateway slot; A6 adds its cron entry in this directory and owns that file. Z4 creates `deploy/vps/` but never `crontab.factory`.
